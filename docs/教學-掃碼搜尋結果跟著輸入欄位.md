# 教學：掃碼搜尋結果跟著輸入欄位走

> 目標：在「新增明細（掃碼或搜尋）」區塊，
> - 在**上面的掃碼框**（`scan-input`，條碼槍、相機、鍵盤）輸入 → 搜尋結果顯示在**掃碼框正下方**
> - 在**下面的物料欄**（`scan-item`）輸入 → 搜尋結果顯示在**物料欄下方**（維持現狀）
>
> 只改 1 個檔案：`src/Warehouse.Web/wwwroot/js/doc-scan.js`，共 3 處。不動後端、不動資料庫、不影響庫存交易。

---

## 0. 先了解現在怎麼運作

| 位置 | 內容 |
|---|---|
| `src/Warehouse.Web/Pages/Shared/_ScanPanel.cshtml` 第 19–23 行 | 上方的掃碼框 `<div class="scan-bar">…<input id="scan-input">` |
| 同檔第 70–72 行 | 下方的物料欄 `scan-item`，以及搜尋結果的容器 `<div class="scan-results" id="scan-item-results">` |
| `doc-scan.js` 的 `searchItems(text)`（約第 324 行） | 把候選物料清單塞進 `scan-item-results` |
| `doc-scan.js` 的 `onScan(value, source)`（約第 387 行） | 每一筆輸入都會經過這裡；查不到精確的料號／條碼／儲位時呼叫 `searchItems` |

**資料流：**

```
掃碼框按 Enter ──► scanner.enqueue(值, 'keyboard')  ┐
相機掃到       ──► scanner.enqueue(值, 'camera')    ├─► onScan(值, source) ─► 查不到精確結果 ─► searchItems(值)
物料欄按 Enter ──► scanner.enqueue(值, 'item-field') ┘                                          │
                                                                                                ▼
                                                                    結果固定塞進物料欄下面的 scan-item-results
```

問題就在最後一步：不管從哪裡輸入，結果容器的位置都寫死在物料欄下面。
所以從上面掃碼框輸入時，眼睛要往下找結果。

**改法：** 結果容器只有一個，我們在顯示之前，用 `source`（輸入來源）決定把這個容器**搬到**哪裡：
- `source === 'item-field'` → 搬到物料欄下面
- 其他（`keyboard`、`camera`）→ 搬到掃碼框下面

> 為什麼用 `source` 而不是 `document.activeElement`（目前焦點）？
> 搜尋是非同步的（要等伺服器回應），等結果回來時焦點可能已經被移走（例如使用者按了 Tab，或程式自己 `focusScan()`）。
> `source` 是「按 Enter 那一刻是哪個欄位」，在佇列裡一路帶著，不會被後來的焦點變化影響，結果比較穩定。
> 對使用者來說效果就等於「依照當時 focus 的欄位」。

## 1. 修改步驟

用 VS Code（或 Visual Studio）開啟：

```
C:\CodeProject\物料管理系統\src\Warehouse.Web\wwwroot\js\doc-scan.js
```

> 建議：目前分支是 `fix/D-33-opening-empty-location`，還有沒 commit 的 D-33 修改。
> 先把 D-33 處理完，再從 `main` 開新分支（例如 `feature/scan-results-position`）來做這個改動，兩件事才不會混在一起。

### 修改 1：新增 `placeResults` 函式

按 `Ctrl+F` 搜尋 `function hideResults`，找到這段（約第 250 行）：

```js
  function hideResults() {
    el.itemResults.hidden = true;
    el.itemResults.textContent = '';
  }
```

在它**正下方**貼上：

```js

  // 搜尋結果放在使用者剛才輸入的欄位旁邊：物料欄輸入的放物料欄下面，掃碼框（條碼槍、相機、鍵盤）輸入的放掃碼框下面
  function placeResults(source) {
    var anchor = source === 'item-field' ? el.itemInfo : panel.querySelector('.scan-bar');
    if (anchor.nextElementSibling !== el.itemResults) anchor.after(el.itemResults);
  }
```

說明：
- `el.itemInfo` 是物料欄下面那行灰字（`scan-item-info`），原本結果容器就緊接在它後面，所以「搬回去」就是放到它後面。
- `panel.querySelector('.scan-bar')` 找到上方掃碼框那一列。
- `anchor.after(x)`：把 `x` 這個元素**移動**到 `anchor` 的後面（同一個元素不會變兩份，是搬家）。Chrome 54 起就支援，符合 Chrome 109 基準。
- `if (... !== ...)`：已經在正確位置就不動，避免多餘的畫面重排。
- 因為是搬同一個元素，按鈕上的點選事件、`hideResults()` 都不用改。

### 修改 2：`searchItems` 多收一個參數並先搬位置

搜尋 `async function searchItems`，把：

```js
  async function searchItems(text) {
```

改成：

```js
  async function searchItems(text, source) {
```

再往下幾行找到：

```js
    el.itemResults.textContent = '';
    el.itemResults.hidden = false;
```

在這兩行**上面**加一行：

```js
    placeResults(source);
```

改完應該長這樣：

```js
    placeResults(source);
    el.itemResults.textContent = '';
    el.itemResults.hidden = false;
```

### 修改 3：呼叫時把 `source` 傳進去

搜尋 `await searchItems(`，在 `onScan` 裡（約第 419 行）：

```js
        var found = await searchItems(value);
```

改成：

```js
        var found = await searchItems(value, source);
```

存檔。完成。

## 2. 驗證

### 啟動

在專案根目錄的 PowerShell：

```powershell
dotnet run --project src/Warehouse.Web
```

> JS 是靜態檔，`asp-append-version="true"` 會在檔案變動後自動換網址，正常不需清快取；若畫面沒變化，在瀏覽器按 `Ctrl+F5`。

### 測試案例

開一張草稿單據（入庫／出庫／移庫任一）或期初建帳的明細頁：

| # | 操作 | 預期結果 |
|---|---|---|
| 1 | 在**上方掃碼框**輸入一個品名關鍵字（不是完整料號），按 Enter | 候選清單出現在**掃碼框正下方** |
| 2 | 點清單中的一個物料 | 清單消失，物料帶入物料欄 |
| 3 | 在**下方物料欄**輸入關鍵字，按 Enter | 候選清單出現在**物料欄下方** |
| 4 | 接著再到上方掃碼框輸入關鍵字按 Enter | 清單搬回**掃碼框下方**（只會有一份，不會兩處都有） |
| 5 | 在掃碼框掃一個正確料號條碼 | 直接帶入，不出現清單（行為不變） |
| 6 | 手機用相機掃一個查不到的碼 | 清單出現在掃碼框下方 |
| 7 | 在 Chrome 109 重複 1、3、4 | 結果相同 |

### 除錯

- 按 `F12` → Console：
  - 出現 `placeResults is not defined` → 修改 1 沒貼到，或貼到別的函式裡面（要跟 `hideResults` 同一層）。
  - 出現 `Cannot read properties of null (reading 'nextElementSibling')` → `.scan-bar` 找不到，確認 `_ScanPanel.cshtml` 的 `<div class="scan-bar">` 還在。
- 清單永遠在下面 → 修改 3 沒改，`source` 傳成 `undefined`；或瀏覽器還在用舊 JS（`Ctrl+F5`）。
- 想看實際搬到哪：F12 → Elements，搜尋 `scan-item-results`，看它的位置。
