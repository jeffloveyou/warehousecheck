# 混合型倉庫庫存系統｜AI 協作開發總計畫 v0.2

**日期：2026-10-21**　**狀態：待正式確認**　**策略：AI Agent 結對開發、由使用者主導與逐步接手維護**

## 1. 專案願景與成功標準
建置一套可自行掌握原始碼與資料的內部倉庫管理系統，支援機械零件、電控材料、生產原料、半成品、成品和耗材，供手機、Windows 電腦＋條碼槍、Android 工業 PDA 共用。起始時無既存庫存表，從物料建檔、儲位編碼、期初盤點建立基線。

**雙重目標**：
- 產品：庫存準確、作業可追溯、搜尋容易、可備份還原，可由現場使用。
- 人才：使用者懂得整體分層、能讀懂核心流程、可以自己完成一般修正並寫出測試，不受 AI Agent 綁定。

**完成定義**：核心功能通過驗收、三種設備實測、備份還原演練、資安基本檢查、README/開發手冊/部署手冊/故障排查更新且具備可照文件自行修改與維護的操作說明。功能完成不等於專案完成。

## 2. 工作方式：Agent 是結對工程師與教師
- 每張任務遵循 **需求確認 → 方案講解 → 檔案級修改計畫 → 使用者批准 → Agent 小範圍改碼 → 使用者本機執行驗證 → Agent 解釋與文件更新**。
- 不讓 Agent 一口氣產出整套系統；每個里程碑要有可執行、可測試的垂直切片（UI→API→業務邏輯→資料庫）。
- AI 預設只修改檔案；`dotnet`、資料庫遷移、發佈指令由使用者在 PowerShell 親自執行。
- 禁止未經同意跨模組大改、資料庫破壞性操作與無關抽象化。建立問題清單與技術決策 ADR。
- Git 小步提交，繁體中文 commit；每個功能附手冊頁與測試案例，不安排練習題。

## 3. 已知需求與明確限制
1. 使用者設備：手機（Android/iPhone）、Windows 電腦搭配 USB/HID 條碼槍、工業 Android PDA；應用共用一套後端與資料庫。
2. 混合型物料分類與單位；支援一物多儲位、一儲位多物料、多倉庫、批號/序號/效期；追蹤規則依物料設定。
3. 一物一個正式料號（唯一）；使用者可自行新增不限數量的搜尋稱呼、用途、俗名和英文縮寫。
4. **專屬別名**精確對應唯一物料；**共用關鍵字**可對應多物料；搜尋結果必須讓人再次確認料號與規格。
5. 入庫／出庫／移庫／期初建帳／盤點；每次更動有單據、操作人、時間與交易明細。預設禁止負庫存。
6. 尚無庫存表：分階段掃描建檔與期初清點，正式帳與測試資料隔離。
7. 初期以 LAN/Wi-Fi 即時連線，V1 不處理真正離線出入庫；內網亦需可信任 HTTPS。
8. 優先自由／可商用方案，避免第三方強制付費服務；具備完整程式碼、資料備份與移轉能力。

## 4. 建議技術架構（須以 M0 PoC 實測確認）
- C# / .NET 10 LTS、ASP.NET Core Web API；前端先比較 Razor Pages、Blazor 靜態 SSR 與 Blazor WebAssembly，經最低規格電腦 PoC 後才定案。保留 PWA 與手機相機掃碼功能。
- PostgreSQL + EF Core + Npgsql；Web 層不直接存取資料庫。
- Modular Monolith（單體模組化）：Domain / Application / Infrastructure / Api / Web / Tests。
- 手機使用相機解碼，電腦和 PDA 先採 Keyboard Wedge 共用文字輸入；針對現場實機相容性測試。
- 驗證與授權：伺服器檢查每個動作權限；登入會話設計、CSRF、防暴力嘗試、審計要在架構階段定稿。
- 開發環境：Windows + PowerShell；支援本機開發與公司內網部署；不預設需要 Docker。

## 5. 功能範圍與優先度
### V1 必須（MVP）
- 建立料號：分類、品牌、型號、單位、描述、附件或圖片（圖片可先預留）、停用狀態；重複檢查。
- 搜尋：料號、精確識別、別名、共用關鍵字、部分型號、複合詞，提供加入搜尋索引入口及紀錄。
- 倉庫與儲位；條碼掃描與基本標籤；庫存查詢。
- 期初清點、入庫、出庫、移庫、盤點調整；帳務一致性、防重複交易與多使用者併發。
- 基本批號／序號／庫存狀態；帳號、角色、權限、操作日誌、Excel 匯入匯出（先做簡易格式）。
- 三種設備確認（相機、Windows 條碼槍、PDA），備份還原與操作手冊。

### V2 擴充（避免第一版膨脹）
採購單／工單／BOM／生產領料、預留庫存與多階審核、棧板/容器、GS1 複合條碼完整解析、ERP 整合、通知、進階多倉調撥、離線同步、搜尋分析與推薦；優先度依真實使用資料決定。

## 6. 建議程式分層
```text
Warehouse.sln
src/
  Warehouse.Domain/          # Entity、Value Object、業務不變條件
  Warehouse.Application/     # 用例、DTO、介面、權限與交易協調
  Warehouse.Infrastructure/  # EF Core / PostgreSQL、外部整合
  Warehouse.Api/             # API、驗證、組態、例外處理
  Warehouse.Web/             # 輕量化 Web UI、PWA、掃碼（渲染方案待 M0）
tests/
  Warehouse.Domain.Tests/
  Warehouse.Application.Tests/
  Warehouse.Api.IntegrationTests/
  Warehouse.Web.E2E/         # 可於後續加入
 docs/
 scripts/
```

| 階段 | 核心內容 | 必須可展示的結果 | 手冊交付重點 |
|---|---|---|---|
| M0 基礎／PoC | 技術基線、舊機基線、Windows/NAS、雙版本更新 PoC、Git 與解決方案 | 記錄各環境測試證據及技術決議 | 系統分層、測試、部署 PoC 實際步驟 |
| M1 物料 | 分類、單位、物料、重複檢查 | 新增／編輯／查詢物料 | DTO、EF Core、Migration、唯一約束的修改位置 |
| M2 搜尋 | 精確識別、專屬別名、共用關鍵字、搜尋排序 | `伺服AMP` 多物料、專屬別名精確定位 | 正規化、SQL 索引、分頁、效能排查 |
| M3 儲位 | 倉庫、儲位、期初建帳 | 掃儲位與物料，建立期初量 | UI → API → DB 資料流追蹤 |
| M4 庫存核心 | 入、出、移庫、異動歷史、併發、冪等 | 多人同時出庫不超賣、重試不重扣 | 交易、鎖、冪等及問題重現方法 |

## 8. 文件即程式交付的一部分
每個功能完成當下同步更新：
1. 需求與驗收案例。
2. 架構圖、資料流（UI → API → Service → Repository → DB）。
3. 開發手冊的新增功能教學：用途、改哪些檔、範例、測試、常見錯誤。
4. API 文件、資料庫 migration、權限表、部署／回滾方式。
5. 每次重大設計決策的 ADR（背景、選項、取捨）。

文件應能回答：「如果今天沒有 AI Agent，我要去哪個檔案找到出庫邏輯？如何新增一種查詢欄位？如何知道沒有破壞舊功能？」

## 9. 安全、品質與資料保護
- HTTPS、登入、伺服器側授權、輸入驗證、參數化 SQL、防 XSS/CSRF；詳細機制由技術 ADR 決定。
- EF Core Migration 納入 Git；每次變更資料表先備份與評估相容性，不在正式環境自動做破壞性 migration。
- 修改庫存只能透過交易服務；Movement 與 Balance 同一 transaction；`idempotencyKey`、版本或列鎖阻止重複扣帳與超賣。
- 計量採 decimal，禁止浮點誤差；基礎單位與精度須固定規則。
- 伺服器儲存 UTC 時間，UI 顯示台灣當地時間；使用者資料、憑證、連線字串不提交 Git。
- 設計日常備份、異機保留、定期還原演練；需要記錄復原點／復原時間目標，V1 上線前確認。

## 10. 開發流程與變更控管
- 單一待辦清單；每個任務卡明列範圍、完成條件、測試與文件更新。
- Agent 先讀現有實作與文件再建議修改；要求提出「為什麼、改哪裡、怎麼驗證」。
- 人類明確同意後才修改，完成後人類執行 `dotnet build` 與 `dotnet test`，將結果交給 Agent 分析。
- 使用者理解關鍵流程後才提交 Git；繁中提交訊息，例如 `feat: 新增物料別名與共用關鍵字搜尋`。
- 每個里程碑做一次人工 code walkthrough，並補齊開發手冊的修改與除錯說明。

## 11. 主要風險與對策
- **物料重複建檔**：建立物料前查料號／原廠型號／條碼／別名相似候選，正式建檔由授權角色確認。
- **搜尋誤判**：別名與共用關鍵字分開、結果保留料號與規格；模糊結果絕不自動出庫。
- **多人併發錯帳**：交易、唯一請求鍵、庫存檢查、整合測試。
- **無既有台帳**：期初庫存透過實際盤點與建帳單，明確標記未清點品項。
- **PDA 相容性差異**：M0~M2 預先用代表性設備驗證 HID、Enter、焦點、Wi-Fi，避免末期發現不相容。
- **AI 生碼無人理解**：小切片實作、逐行說明、文件與測試必須同步。
- **過度設計**：先完成單倉簡單端到端，再擴充多倉與進階物料規則。

## 12. 新增的三項非功能需求（最高優先級）
1. **低規格使用者端**：手機、PC、PDA 共用系統但前端低負載；伺服器端分頁、按需載入掃碼程式、低背景輪詢、實機效能基準。
2. **Windows PC／Linux NAS 皆可部署**：程式碼與設定分離，保留不同 Runtime Identifier 的發布能力；NAS 是否可跑 .NET、PostgreSQL、容器、雙實例，均依實機驗證。
3. **不中斷正常作業的線上更新**：優先 Blue-Green + 反向代理 + 健康檢查 + 請求排空 + 向下相容資料庫變更。單機主機、資料庫或 NAS 故障不保證不中斷。

上述三項必須在 **M0 先做 PoC**，且納入最終驗收。詳細內容參閱 `docs/10-低負載與跨平台部署.md`、`docs/11-線上更新與回滾.md`。

## 13. 正式交付物
- 程式碼、SQL Migration、測試及真實執行結果。
- Windows PC 與已選定 NAS 的安裝／備份／復原步驟及配置範例。
- 人類可操作的 `scripts/publish.ps1`，支援 Self-contained 與 Framework-dependent；發布產物不可入 Git。
- 可演練的更新、健康檢查、版本切換、回滾與交易一致性測試。
- 以繁體中文持續維護的開發手冊、操作手冊、日誌及 ADR；**不含練習題**。
