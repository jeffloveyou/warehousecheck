# 開發手冊｜從第一天開始寫、隨功能成長

> 本文件是**持續更新的開發教材**。以下章節目前為基線及待完成事項，不應誤認系統已實作。每次完成程式變更都應同步更新對應章節，並在標題標出對應版本或 commit。

## 0. 文件用途與閱讀方式
本手冊持續記錄一個完整請求的路徑：`Web 頁面 → HTTP API → Application Service → Domain Rule → EF Core → PostgreSQL → 回傳結果`。接著了解 DTO、依賴注入、Migration、測試與日誌。看得懂比「AI 一次做完」重要。

### 常用指令（在專案根目錄執行）
```powershell
.\scripts\check-env.ps1          # 環境檢查（唯讀）；全部 [OK] 才繼續
dotnet build .\Warehouse.slnx     # 預期：0 個警告、0 個錯誤
dotnet test  .\Warehouse.slnx     # 預期：「測試回合摘要： 成功!」
git status; git diff; git log --oneline
```
- `.\scripts\bootstrap-solution.ps1` 只在建立專案時執行過一次，之後不要再執行（`src/` 已存在時會自動停止）。
- Git 流程：每個任務開 `feature/<任務ID>-<簡述>` 分支，完成後以 PR 合併到 `main`；commit 訊息使用繁體中文。
- 新增 NuGet 套件前需查證授權並經使用者核准，核准後記錄在對應章節。

## 2. 專案導覽（M0-02）
```text
物料管理系統/
├─ Warehouse.slnx                  # solution（.NET 10 的 XML 格式）
├─ global.json                     # 固定 SDK 版本；指定測試使用 Microsoft.Testing.Platform
├─ Directory.Build.props           # 全部專案共用：Nullable、ImplicitUsings、警告視為錯誤
├─ src/
│  ├─ Warehouse.Domain/            # 實體、值物件、不能破壞的業務規則；不依賴任何其他層
│  ├─ Warehouse.Application/       # 使用案例、服務介面（如 InventoryPostingService）
│  ├─ Warehouse.Infrastructure/    # EF Core DbContext、Migration、Repository 實作
│  ├─ Warehouse.Api/               # HTTP 端點、授權、驗證、錯誤格式（類別庫）
│  └─ Warehouse.Web/               # 主程式：UI＋載入 Api 端點，只部署這一個服務
├─ tests/
│  ├─ Warehouse.UnitTests/         # 單元測試、分層依賴測試
│  └─ Warehouse.IntegrationTests/  # 連 PostgreSQL 的整合／併發測試（M0-04 起）
└─ scripts/                        # check-env.ps1、bootstrap-solution.ps1
```

### 依賴方向（只允許外層 → 內層）
```text
Web ──> Api ────────────> Application ──> Domain
 └────> Infrastructure ──────┘
```
- 由各 `.csproj` 的 `ProjectReference` 決定；Domain 沒有任何專案參考。
- `Warehouse.Api` 是類別庫，以 `<FrameworkReference Include="Microsoft.AspNetCore.App" />` 使用 ASP.NET Core 型別，由 `Warehouse.Web` 載入（ADR-0006）。
- 防護測試：`tests/Warehouse.UnitTests/Architecture/LayerDependencyTests.cs` 檢查 Domain、Application 沒有實際使用 EF Core、ASP.NET Core、Npgsql 或外層組件；透過 `src/Warehouse.Domain/AssemblyMarker.cs`、`src/Warehouse.Application/AssemblyMarker.cs` 取得組件。編譯器只保留實際用到的引用，所以這是「實際使用」的檢查。
- `tests/Warehouse.IntegrationTests/UnitTest1.cs` 是範本測試，M0-04 加入健康檢查整合測試時取代。

### 常見錯誤與處理
| 現象 | 原因 | 處理 |
|---|---|---|
| build 出現原本只是警告的錯誤（如 `CS8618`） | `Directory.Build.props` 設定 `TreatWarningsAsErrors` | 修正程式；不要關閉此設定 |
| `A compatible .NET SDK was not found` | 本機 SDK 低於 `global.json` 的 10.0.402 | 安裝 .NET 10 SDK 最新版 |
| `dotnet test` 顯示 0 個測試並失敗 | Microsoft.Testing.Platform 在沒有測試時回傳失敗 | 每個測試專案至少保留一個測試 |
| `LayerDependencyTests` 失敗並列出組件名稱 | 內層程式用了外層或基礎設施型別 | 把程式移到正確的層，或改經 Application 介面 |

## 8. 版本控制與更新政策
- 文件與程式在同一個 Git repository，文件缺漏代表功能交付未完成。
- API 或資料庫結構改動時，手冊的檔案路徑與指令必須同步更新。
- 每個里程碑檢查一次手冊的指令、路徑及故障排查步驟是否仍符合實際程式，錯誤或過時內容必須修正。

## 12. 線上更新與回滾教學（M0 PoC 後補實際配置）
- 應用 A/B 並行、反向代理的切換點、健康檢查、請求排空和停止舊版的理由。
- 如何識別目前版本、確認新版本已接流量、觀察錯誤率、確定沒有重複扣帳。
- 為何 PWA 舊資源可能繼續使用、如何通知使用者安全更新，而不清除未提交資料。
- PostgreSQL schema Expand → Migrate → Contract 變更順序、備份、回滾相容性。
- 發布／回滾指令、預期輸出、故障排查和更新紀錄皆須對應真實實作。
