# ADR-0005：開發環境、M0 範圍與 AI 角色

- 狀態：已接受（Accepted）
- 日期：2026-10-21
- 批准：使用者（產品負責人）

## 背景
開始 M0 前需確定開發工具、PoC 範圍、效能基線與更新策略；使用者另要求建立 AI 角色，依任務選用不同模型以節省 token。

## 決策
| ID | 主題 | 決策 |
|---|---|---|
| D-14 | 開發工具 | Windows 11＋PowerShell 7、VS Code＋C# Dev Kit、.NET SDK 10（開發機已安裝 10.0.402）、Git＋GitHub `jeffloveyou/warehousecheck` |
| D-14 | 開發 DB | Windows 原生安裝 PostgreSQL（EDB 安裝程式）；整合與併發測試連本機測試資料庫。開發機不使用 Docker |
| D-10/24 | 規模 | 大型：超過 30 名使用者或 20,000 料號。效能測試以 **20,000 料號、30 名同時操作員**起測 |
| D-15 | 最舊電腦 | Windows 10、雙核心、4 GB RAM、Edge；M0 仍需在實機量測 |
| D-16 | 前端比較 | M0 只完整比較 **Razor Pages** 與 **Blazor 靜態 SSR**；Blazor WebAssembly 只量測空白範本的首次載入量作參考 |
| D-17/18/20 | 伺服器 | NAS 與 PC 尚未決定。M0 在開發機做 PoC；因規模大，PostgreSQL 傾向獨立主機，NAS 傾向用於備份與附件，正式選型 M7 前確認 |
| D-21 | 更新策略 | 開發與試運轉期間採下班維護窗口；M0 只做小型 A/B 切換 PoC；**M7 正式上線前完成藍綠部署** |
| D-09 | HTTPS | 自建內部 CA（mkcert 或公司內部 CA）簽發內網網域憑證，根憑證安裝到電腦、手機、PDA；開發機可先用 `dotnet dev-certs` |

## AI 角色與模型分派
角色定義在 `.claude/agents/`，分派規則見 `AGENTS.md` 第十節。

| 角色 | 模型 | 理由 |
|---|---|---|
| `warehouse-architect` | Opus | 架構與 ADR 決策錯誤的代價高 |
| `warehouse-reviewer` | Opus | 庫存、併發、安全問題需要最仔細的推理 |
| `warehouse-implementer` | Sonnet | 依已批准計畫實作，性價比最佳 |
| `warehouse-test-writer` | Sonnet | 測試需理解業務規則，但範圍明確 |
| `warehouse-doc-writer` | Haiku | 依提供的事實整理文件，推理需求低 |
| `warehouse-explorer` | Haiku | 唯讀搜尋與摘要 |

## 後果
- 手冊與指令以 VS Code、PowerShell、原生 PostgreSQL 為準。
- 開發機無 Docker，Testcontainers 不列為預設；整合測試需有本機測試資料庫連線設定。
- NAS 容器部署的驗證延到取得設備後；M0 Linux PoC 僅證明 linux-x64 相容性。
- 派工本身有重複上下文成本；小改動仍由主對話直接處理。
