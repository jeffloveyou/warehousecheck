# ADR-0015：進出倉單據、審核與預留連動、用途與往來對象主檔（M4-02）

- 狀態：已接受（Accepted），M4 計畫經使用者 2026-10-22 核准
- 相關：FR-05、FR-08、ADR-0003（D-07）、ADR-0004（決策三、併發控制）、ADR-0014、`docs/04` §17

## 背景
期初之後的庫存異動（進倉、出倉、移庫）需要正式單據：有單號、可審核、可列印、可追查，而且草稿與待核准都不能影響結存。使用者 2026-10-22 決定：
- 用途類型：可維護清單。
- 廠商／客戶／部門：建立主檔。
- 移庫：可以跨倉。
- 進出倉單的自核：獨立設定（預設不允許）。

## 決策
1. **沿用同一張單據表**：`stock_documents.doc_type` 新增 `Inbound`、`Outbound`、`Transfer`。
   - 狀態沿用 Draft／Submitted／Posted／Cancelled。退回＝回到 Draft 並記錄原因。
   - 單號各自用 sequence 產生：`IN-`、`OUT-`、`TR-` 加六位數，跳號可接受。
2. **表頭欄位**：
   - `purpose_id`（`document_purposes`，分進／出方向）、`partner_id`（`business_partners`，類型 Vendor／Customer／Department）、`external_no`、`note`、`reversal_of_document_id`。
   - 各欄位可開關、可設必填（`stock.documents.field.*`）。預設：用途啟用＋必填，其餘啟用＋選填。
   - 欄位關閉時不接受新值，也不刪除既有值。必填在送審或確認時才檢查，草稿可以先存。
   - 移庫單沒有用途；沖銷單不檢查用途。
3. **明細**：
   - 數量必須 > 0，不能「確認為空」。
   - 移庫必填 `target_location_id`，不可等於來源，可在其他倉庫。
   - `reservation_id`：出倉單依手動預留出庫時使用。
   - 單內唯一鍵加入目的儲位；送出後新欄位也不可修改（`stock_document_lines_protect`）。
4. **審核**（`stock.documents.approval_enabled`，預設關閉）：
   - 關閉：草稿 →「確認」直接過帳（確認者記為核准者）；不能送審。
   - 開啟：草稿 → 送審 → 倉庫主管核准＝過帳；不能直接確認。
   - 自核依 `stock.documents.allow_self_approval`，與期初的 D-07 開關分開。
   - 送審後才把審核關閉的單，仍由主管核准。
5. **審核與預留連動（D-26，ADR-0004 決策三）**：
   - 出倉單送審時，同一交易依料號合計建立倉庫層級預留：`reference_type = 'StockDocument'`、`reference_id = 單據`。
   - 預留用 `ReserveManyAsync`，所有鎖一次排序取得；不足就無法送審。
   - 已指定手動預留的明細不重複預留。
   - 核准時，各明細沖銷本單預留（或指定的預留）；沒沖完的剩餘量在同一交易釋放。
   - 退回、取消時釋放本單預留。
   - 進倉、移庫送審時不預留（移庫在核准時才檢查可用量）。
   - 停用的物料也可送審預留（可出倉清空庫存）。
   - 允許負庫存的物料只預留「目前可用的部分」（`min(倉庫可用量, 全倉可用量＋下限)`，不小於 0；使用者 2026-10-22 決定），不足的部分在核准時依負庫存規則檢查。
   - 明細指定手動預留時，送審只補預留「超出手動預留剩餘量」的部分；核准時先沖手動預留，超出部分沖本單預留。
   - 出倉單送審自動建立的預留（`StockDocument` 類型）不能被其他單據指定（`reservation.not_selectable`），過帳前再檢查一次。
6. **過帳**：確認與核准共用同一流程。
   - 儲位（來源＋目的）依 id `FOR UPDATE`，並檢查歸屬。
   - 批號、序號：進倉時沒有就建立；出倉、移庫必須已存在。
   - 組結存變化：進 +q；出 −q；移庫為來源 −q、目的 +q，同一批號與序號。
   - 交給 `ApplyAsync`。鎖順序見 ADR-0004「併發控制」規則 8。
   - 批號、序號解析與明細回填都是批次 SQL（500 行序號出倉確認約 100 ms，T-M4-02-12）。
7. **冪等**：送審、確認、核准都要冪等鍵。
   - `RequestHash = 命令|單據|版本|操作者`，冪等紀錄與業務資料同一交易寫入。
   - 鎖住單據後再查一次冪等紀錄。
8. **沖銷單**：
   - 只限已過帳的進出倉、移庫單。產生方向相反的草稿：入↔出；移庫則來源與目的互換，目的儲位必須同屬一個倉庫。
   - 一張單只能有一張未取消的沖銷單（部分唯一索引 `ux_stock_documents_reversal`）。
   - 沖銷單本身不能再沖銷。
9. **主檔**：代碼英數字（可含 `-`、`_`），最多 20 字，轉大寫；同類型內唯一；建立後不可改；不刪除，只停用。
   - 維護權限：倉庫主管、物料管理員。
   - 停用後新單據不能選，舊單據保留原值。
10. **權限**：
    - `Stock.Document.Edit`（作業員、倉庫主管）：建立、改草稿（限建立者或主管）、送審、確認、取消、建立沖銷單。
    - `Stock.Document.Approve`（倉庫主管）：核准、退回。
    - 沖銷單任何有 `Stock.Document.Edit` 的人都可以建立（使用者 2026-10-22 決定：作業員本來就能開一般進出倉單）。

## 後果
- 停用的物料仍可出倉、移庫，用來清空庫存；不可再進倉。
- **A/B 相容限制**：舊版程式（M4-02 以前）的 `StockDocumentType` 只有 `Opening`。資料庫一旦有進出倉單，舊版讀到這些單據的異動（例如 `/Stock` 的最近異動）會因不認得列舉值而出錯。
  - 正式上線時，進出倉功能的第一版不能和 M4-02 以前的版本同時運作。
  - 開發機目前沒有進出倉單資料，舊版 A 槽位不受影響。
- 待補：附件、列印（M4-12）、畫面（PR3）；手動預留畫面（PR4）。

## 補充（2026-10-22，M4-03～05，使用者決定）
1. **附件**：JPEG／PNG／WebP／PDF，每檔 10 MB、每張單最多 10 個；草稿可移除，送出或過帳後只能新增（trigger 保證）。PDF 以附件下載，不在瀏覽器內開啟。
2. **列印**：瀏覽器列印樣式（不引入伺服器端 PDF 套件）；公司名稱（系統設定）、表頭、明細、簽名欄「經手人／主管／領料人或收料人」；未過帳加浮水字。
3. **料號輸入**：輸入或掃碼後按 Enter 搜尋，精確命中才帶入，否則列候選點選；不做逐字即時建議（舊電腦低負載）。
4. **建單冪等**：建立表單帶請求 ID（當單據 ID），連點或重送只有一張；別人用同一個 ID 被拒（`document.request_id_conflict`）。
5. **手動預留可設到期時間**，過期自動釋放（ADR-0004 補充）；異動匯出留到 M6-03。
