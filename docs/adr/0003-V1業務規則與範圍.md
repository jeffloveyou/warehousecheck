# ADR-0003：V1 業務規則與範圍

- 狀態：已接受（Accepted）
- 日期：2026-10-21
- 批准：使用者（產品負責人）

## 背景
`docs/08-待決事項.md` 中多項業務規則影響 M1–M4 的資料模型與流程，需在 M0 前定案，避免日後以 Migration 大幅修改。

## 決策
| ID | 主題 | 決策 |
|---|---|---|
| D-01 | 正式料號 | 分類前綴＋流水號，例如 `EL-000125`；前綴可在分類設定；由系統產生，`ItemId`（UUID）為永久內部識別 |
| D-02 | 物料建檔 | 作業員可提出「待核准」物料，物料管理員確認無重複後核准生效；**待核准物料不可交易** |
| D-03 | 專屬別名 | 由 DB 唯一約束檢查無衝突即生效，留稽核；管理員可事後停用。共用關鍵字員工可直接新增 |
| D-05 | 儲位 | 同一儲位允許混放多料號；負庫存例外見 ADR-0004 |
| D-06 | 追蹤模式 | 每料號設定 `TrackingMode` = `None`／`Lot`／`Serial`；V1 同時支援批號與序號 |
| D-07 | 期初／盤差核准 | **可設定**：系統設定選「建立者不可自核」（預設）或「允許自核」；兩種模式都記錄建立者、核准者與時間 |
| D-08 | 掃碼設備 | PDA 與條碼槍尚未採購；M0 以手機相機與鍵盤模擬輸入測試，實機列待測 |
| D-11 | V1 範圍 | **V1 包含預留庫存**（規則見 ADR-0004）；採購單、工單、BOM、ERP 整合不在 V1 |
| D-12 | 登入與離線 | ASP.NET Core Identity＋Cookie 自建帳號；V1 不支援離線庫存交易 |
| — | 條碼 | 物料與儲位條碼皆為**選配**。沒有條碼時，搜尋＋點選必須能完成全部作業；使用條碼時採 **QR Code**；V1 不實作標籤列印，測試標籤由使用者自行製作（M7-03 起有儲位 A4 標籤列印，見 ADR-0020） |

## 後果
- `Items` 需有狀態（如 `PendingApproval`、`Active`、`Inactive`），交易服務必須拒絕非 `Active` 物料。
- `ItemCategories` 需保存料號前綴與流水號產生規則；流水號產生需在併發下唯一（DB sequence 或鎖定的計數列）。
- 系統設定表需保存 D-07 核准模式；變更此設定本身要留稽核。
- 每個入庫、出庫、移庫、盤點畫面都必須有「搜尋選擇」路徑，掃碼只是加速輸入。
- 掃碼 Parser 以 QR Code 內容為主，但仍經同一文字解析介面，保留 HID／PDA 鍵盤輸入相容。

## 驗證
- M1：待核准物料無法出入庫的測試；料號流水號併發產生不重複的測試。
- M2：專屬別名併發新增只有一筆成功。
- M5：無條碼情況下以搜尋完成入庫、出庫、移庫的驗收案例。
