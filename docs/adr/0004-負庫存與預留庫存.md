# ADR-0004：負庫存例外與預留庫存

- 狀態：已接受（Accepted）
- 日期：2026-10-21
- 批准：使用者（產品負責人）

## 背景
AGENTS.md 第六節規定「預設不得負庫存」，例外須獨立 ADR。使用者決定部分料號（例如先領後補的耗材）允許負庫存，且 V1 納入預留庫存。兩者都直接影響可用量計算與出庫併發控制，是庫存正確性風險最高的部分。

## 決策一：負庫存例外
1. 預設所有料號**禁止**負庫存。
2. 只有 `TrackingMode = None` 的料號可開啟負庫存；`Lot`、`Serial` 料號一律禁止（無法得知負數屬於哪個批號或序號）。
3. 料號欄位：
   - `Items.AllowNegativeStock`（bool，預設 false）
   - `Items.NegativeStockLimit`（decimal，≥ 0，表示結存最低可到 `-NegativeStockLimit`）
4. 開啟或修改這兩個欄位需物料管理員權限並留稽核。已有負結存時，不可關閉 `AllowNegativeStock` 或把下限調到比目前結存更高。
5. 出庫後結存變成負數時：Movement 照常寫入並標記，同時寫稽核；負結存出現在「待補帳」清單，直到補入庫使結存 ≥ 0。
6. 下限檢查與扣減在同一 DB 交易內以條件式更新完成：`UPDATE ... SET Quantity = Quantity - @qty WHERE ... AND Quantity - @qty >= -@limit`；影響列數為 0 即拒絕。

## 決策二：預留庫存（V1）
1. 粒度：**料號＋倉庫**（`StockReservations`：`ReservationId`、`ItemId`、`WarehouseId`、`Quantity`、`ReferenceType`、`ReferenceId`、`Status`、`CreatedBy`、時間）。不鎖定儲位、批號或序號；出庫時才指定實際庫存維度。
2. 可用量（倉庫層級）：
   ```text
   可用量 = Σ 該倉 AVAILABLE 狀態結存 − Σ 該倉未清除預留量
   ```
   `QUARANTINE`、`BLOCKED` 等受限狀態不計入可用。
3. 建立預留時，可用量必須足夠（允許負庫存的料號也不能「預留不存在的庫存」，除非另經 ADR 核准）。
4. 依預留出庫時，在同一交易中扣減結存並沖銷對應預留量，避免預留被重複計算。
5. 非依預留的出庫，必須確認出庫後「可用量 ≥ 0」（允許負庫存的料號，以 `-NegativeStockLimit` 為下限），不可吃掉別人已預留的數量。
6. 預留的建立、取消、沖銷都需 `Idempotency-Key` 並寫稽核。

## 決策三：待核准出倉單自動預留（2026-10-21 補充，ADR-0006）
1. 只在系統設定開啟「單據審核」時適用。
2. 出倉單送審時，依明細建立倉庫層級預留（`ReferenceType = StockDocument`），可用量不足即無法送審。
3. 核准過帳時，在同一交易中扣減結存並沖銷預留；退回、取消時釋放預留。
4. 預留的建立、沖銷、釋放皆走冪等與稽核規則。

## 併發控制
- 同一料號＋倉庫的預留與出庫可能互相競爭。建議以「料號＋倉庫」為單位取得交易層級鎖（例如 PostgreSQL `pg_advisory_xact_lock` 或鎖定彙總列），再檢查可用量並寫入；實際做法在 M4 實作前由 `warehouse-architect` 比較後補充本 ADR。
- 所有檢查與寫入在同一交易內完成；快取不得參與可用量判定。

## 後果
- `docs/02-架構與資料庫.md` 的 `Items`、`StockReservations` 定義需配合調整。
- 出庫流程比原設計多一層「倉庫可用量」檢查，M4 需實測併發效能。
- 「待補帳」清單成為 V1 必要畫面／查詢。

## 必要測試
- `Lot`／`Serial` 料號嘗試開啟負庫存 → 拒絕。
- `None` 料號下限 5，結存 2，出庫 7 → 成功，結存 −5；再出庫 1 → 拒絕。
- 兩個並行出庫合計超過下限 → 只有一筆成功。
- 結存 10、已預留 8，非預留出庫 3 → 拒絕；依預留出庫 8 → 成功且預留沖銷。
- 並行建立預留與出庫 → 不出現可用量 < 0。
- 同一 `Idempotency-Key` 重送預留 → 只建立一筆。
- 已有負結存時關閉 `AllowNegativeStock` → 拒絕。
