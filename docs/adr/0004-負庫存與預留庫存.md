# ADR-0004：負庫存例外與預留庫存

- 狀態：已接受（Accepted）
- 日期：2026-10-21
- 批准：使用者（產品負責人）

## 背景
AGENTS.md 第六節規定「預設不得負庫存」，例外須獨立 ADR。使用者決定部分料號（例如先領後補的耗材）允許負庫存，且 V1 納入預留庫存。兩者都直接影響可用量計算與出庫併發控制，是庫存正確性風險最高的部分。

## 決策一：負庫存例外
1. 預設所有料號**禁止**負庫存。
2. 只有 `TrackingMode = None` 的料號可開啟負庫存；`Lot`、`Serial` 料號一律禁止（無法得知負數屬於哪個批號或序號）。
3. 料號欄位：
   - `Items.AllowNegativeStock`（bool，預設 false）
   - `Items.NegativeStockLimit`（decimal，≥ 0）：料號**全倉合計可用量**最低可到 `-NegativeStockLimit`（使用者 2026-10-22 決定；單一儲位不另設下限）
4. 開啟或修改這兩個欄位需物料管理員權限並留稽核。已有負結存時，不可關閉 `AllowNegativeStock`；不可把下限調到比目前全倉合計可用量的負數部分更小。
5. 出庫後結存變成負數時：Movement 照常寫入並標記，同時寫稽核；負結存出現在「待補帳」清單，直到補入庫使結存 ≥ 0。
6. （2026-10-22 修訂）下限檢查與扣減在同一 DB 交易內：不允許負庫存的物料，結存變負由 AFTER trigger `trg_stock_balances_floor` 拒絕（不可用 BEFORE trigger：`ON CONFLICT DO UPDATE` 會先以預定插入列觸發）；允許負庫存的物料，下限為**料號全倉合計可用量 ≥ −NegativeStockLimit**，由過帳後檢查（見「併發控制」）。

## 決策二：預留庫存（V1）
1. 粒度：**料號＋倉庫**（`StockReservations`：`ReservationId`、`ItemId`、`WarehouseId`、`Quantity`、`ReferenceType`、`ReferenceId`、`Status`、`CreatedBy`、時間）。不鎖定儲位、批號或序號；出庫時才指定實際庫存維度。
2. 可用量（倉庫層級）：
   ```text
   可用量 = Σ 該倉 AVAILABLE 狀態結存 − Σ 該倉未清除預留量
   ```
   `QUARANTINE`、`BLOCKED` 等受限狀態不計入可用。**另外，儲位本身必須是有效狀態**：待驗或停用儲位的結存一律不算可用（ADR-0014 決策 7，2026-10-22 補充）。
3. 建立預留時，可用量必須足夠（允許負庫存的料號也不能「預留不存在的庫存」，除非另經 ADR 核准）。
4. 依預留出庫時，在同一交易中扣減結存並沖銷對應預留量，避免預留被重複計算。
5. 非依預留的出庫，必須確認出庫後「可用量 ≥ 0」（允許負庫存的料號，以 `-NegativeStockLimit` 為下限），不可吃掉別人已預留的數量。
6. 預留的建立、取消、沖銷都需 `Idempotency-Key` 並寫稽核。

## 決策三：待核准出倉單自動預留（2026-10-21 補充，ADR-0006）
1. 只在系統設定開啟「單據審核」時適用。
2. 出倉單送審時，依明細建立倉庫層級預留（`ReferenceType = StockDocument`），可用量不足即無法送審。
3. 核准過帳時，在同一交易中扣減結存並沖銷預留；退回、取消時釋放預留。
4. 預留的建立、沖銷、釋放皆走冪等與稽核規則。

## 併發控制（M4 前比較結果，2026-10-22，warehouse-architect 建議、使用者核准 M4 計畫）
### 決策
採「料號＋倉庫」交易層級 advisory lock＋寫入後檢查（post-check），隔離等級維持 READ COMMITTED。不採彙總列 `FOR UPDATE`（多一張需維護的表，常用列反覆寫入）與 SERIALIZABLE（誤判多、需整段重試）。

### 規則
1. 鎖鍵：`AdvisoryLocks.StockKey(itemId, warehouseId)`＝SHA-256("stock-iw:"‖item‖warehouse) 前 8 bytes；允許負庫存物料另用 `StockItemKey(itemId)`。只用 `pg_advisory_xact_lock`（交易結束自動釋放）。**鎖鍵算法不可變更**（A/B 兩版同時運作必須鎖到同一把）；變更需排維護窗口。
2. 取鎖範圍：任何 delta < 0 的明細所屬（料號,倉庫）；允許負庫存物料有扣減時加（料號）；建立預留取（料號,倉庫）與（料號）。去重後依**鍵值**排序取鎖（雜湊碰撞也不會死結，只會多等）。
3. 不取鎖的路徑：入庫、預留釋放（只改 Open 列）、儲位改狀態、倉庫或儲位停用（要求零庫存）。這些只會讓可用量變大，或依 ADR-0014 決策 7 不保證可用量。M6 盤點／調整必須經 `IInventoryPostingService.ApplyAsync`。
4. post-check（取鎖、寫入後的新語句）：
   - 對每個（料號,倉庫）計算本次淨效果 `net = Σ(Available 結存且儲位 Available 的 delta) + 沖銷的預留量`；儲位狀態以本交易 `FOR UPDATE` 讀到的為準。
   - 一般物料：`net < 0` 時檢查倉庫可用量 ≥ 0。
   - 允許負庫存物料：料號各倉 net 合計 < 0 時，檢查**料號全倉合計可用量 ≥ −NegativeStockLimit**（使用者 2026-10-22 決定，取代原「每倉 −limit」）。
   - 負數只能出現在 Available 結存＋有效儲位；待驗儲位不可變負。
   - 建立預留：倉庫可用量 ≥ 0（負庫存物料也一樣）；負庫存物料另要全倉合計可用量 ≥ −limit。
   - 取鎖期間物料剛開啟負庫存（取鎖前讀到關閉、取鎖後讀到開啟）：回 `stock.busy` 請重試（沒拿到料號鎖）。
5. 依預留出庫：預留列 `FOR UPDATE`，確認 Open、料號＋倉庫一致；沖銷 `min(扣減量, 剩餘量)`，超出部分當一般出庫（使用者 2026-10-22 決定）。待驗儲位也可依預留出庫。
6. 批次寫入：同一維度先在程式內合計淨值再 upsert（`ON CONFLICT` 不能在同一指令更新同列兩次），依維度排序。異動後結存由「最終值 − 淨值」回推，同維度內增加在前、扣減在後逐行累加。下限依整張單據的淨值判斷。
7. 物料關閉負庫存或調高下限（M4-08）：先取 `StockItemKey` → `items FOR UPDATE` → 檢查 → 更新。過帳不鎖 items 列。
8. 鎖順序（實作，2026-10-22 M4-02 審查 #7 對齊）：單據 `FOR UPDATE` → 儲位依 id `FOR UPDATE`（呼叫端）→ 批號／序號 upsert（依（物料, 號碼）排序）→ 進入 `ApplyAsync`：儲位（重入，已持有）→ 倉庫依 id `FOR SHARE` → 庫存 advisory 鎖（依鍵值）→ 預留列依 id `FOR UPDATE` → 結存批次 upsert → 異動帳、post-check；最後冪等、稽核。預留建立（含出倉單送審）：單據 → 倉庫 `FOR SHARE` → advisory。批號／序號列只有過帳會寫，倉庫停用不碰它們，所以「批號在倉庫之前」不會形成循環。
9. `SET LOCAL lock_timeout = '5s'`；死結（40P01）、等鎖逾時（55P03）、序列化失敗（40001）一律回 `stock.busy`，整筆回滾。

### 後果
- 快取與彙總表不參與可用量判定。
- 負庫存物料的非預留出庫可吃掉實體上已預留的數量，到全倉 −limit 為止（允許負庫存的固有語意）。
- advisory 鎖占用共用鎖表空位（約 `max_locks_per_transaction ×（max_connections＋預備交易數）`）；500 行單據最多約 1000 把（負庫存物料每料號多一把）。部署前確認目標主機設定（`docs/10`）。
- 實作與測試：`docs/04` §16、`docs/05` T-M4-01-01～22。

## 後果
- `docs/02-架構與資料庫.md` 的 `Items`、`StockReservations` 定義需配合調整。
- 出庫流程比原設計多一層「倉庫可用量」檢查，M4 需實測併發效能。
- 「待補帳」清單成為 V1 必要畫面／查詢。

## 必要測試
- `Lot`／`Serial` 料號嘗試開啟負庫存 → 拒絕。
- `None` 料號下限 5，結存 2，出庫 7 → 成功，結存 −5；再出庫 1 → 拒絕（T-M4-01-04）。
- 兩個並行出庫合計超過下限 → 只有一筆成功。
- 結存 10、已預留 8，非預留出庫 3 → 拒絕；依預留出庫 8 → 成功且預留沖銷。
- 並行建立預留與出庫 → 不出現可用量 < 0。
- 同一 `Idempotency-Key` 重送預留 → 只建立一筆。
- 已有負結存時關閉 `AllowNegativeStock` → 拒絕。

## 補充：預留到期與負庫存設定（2026-10-22，M4-07／08）
- 手動預留可設到期時間（使用者決定）。可用量公式只計 `status = 'Open' AND (expires_at IS NULL OR expires_at > now())`；沖銷已過期的預留回 `reservation.closed`。背景工作每 10 分鐘把到期預留改成 Released 並寫稽核（狀態只是追上，正確性由公式保證）。出倉單送審預留不設到期。
- 關閉負庫存時，除了不可有負結存，**全倉可用量（扣除預留）也不可 < 0**；下限 ≤ 999,999,999、小數位依基本單位。
- 舊版程式（M4-04 以前）不認得 `expires_at`：A／B 並行期間舊版仍把過期預留算進預留（偏保守），也允許沖銷已過期的手動預留；影響只在切換的幾分鐘內，已記於 `docs/11`。
