# ADR-0013：搜尋索引設計（專屬別名、共用關鍵字、搜尋排序）

- 狀態：已接受（Accepted），M2 計畫經使用者 2026-10-22 核准
- 相關：ADR-0003 D-03、`docs/03`、`docs/02`、`docs/04` §4

## 背景
現場人員不必記料號或正式品名，用俗稱、縮寫、用途就能找到正式物料，例如「伺服AMP」「伺服的驅動器」。結果要顯示命中原因，最後一定由人選擇物料。

## 決策
1. **兩張表**：
   - `item_aliases`（專屬別名）：有效的別名全系統唯一，靠部分唯一索引 `ux_item_aliases_active_normalized_text`（`WHERE is_active`）保證。
   - `item_keywords`（共用關鍵字）：同一物料不重複（`ux_item_keywords_active_item_text`），不同物料可以共用。
   - 依 D-03，沒有衝突即生效、記錄建立者，不需要事前核准。
2. **只能加在有效（已核准）的物料**。
   - 待核准物料沒有料號，不加索引。
   - 已停用物料的既有索引仍查得到，結果標示「停用」，但不能再新增。
3. **別名、關鍵字不可使用料號或申請單號的格式**（`^[A-Z0-9]{2,4}-[0-9]{6,}$`，正規化後比對）。
   - 因此暫不建 `docs/02` 提到的 `ExactIdentifierRegistry`。有條碼時（M5）再評估，那時才有第三種精確識別碼。
4. **同一個詞可以是 A 物料的別名、同時是 B 物料的共用關鍵字**。
   - 搜尋時兩筆都列出，各自標示命中原因，由人選擇。
   - 只拒絕同一物料內的重複：同一物料的別名與關鍵字不可同字。想把關鍵字改成別名時，要先停用那個關鍵字。
   - 每個物料最多 20 筆有效別名、100 筆有效關鍵字。
   - 新增時鎖住物料那一列（`FOR UPDATE`），同一物料的新增會排隊。
5. **只停用、不刪除**。
   - trigger `item_index_protect` 禁止 DELETE，也禁止改寫文字、物料、建立者，以及把已停用改回有效。
   - 要恢復就新增一筆，舊紀錄保留，建立者與停用者都可稽核。
6. **權限**：
   - 新增：作業員、物料管理員（政策 `Items.Index`）。
   - 停用：建立者本人或物料管理員。
7. **M2 不使用 pg_trgm**：
   - 依 docs/03 §6，M2 的搜尋是精確比對加部分比對（ILIKE）與多詞比對。
   - 型號另以「去掉符號」的方式比對，所以 `MR J4 40B` 也能找到 `MR-J4-40B`。
   - pg_trgm 要先量測，而且需要建立 extension 的權限，列為待辦。
8. **重複候選加入「別名相同」**：
   - 新物料的品名等於某物料的有效別名時，列為候選。
   - 共用關鍵字本來就會掛多個物料，拿來比對會太多雜訊，所以不納入。

## 後果
- 同時新增同一個別名時，只有一筆成功（資料庫保證），其餘收到 `index.alias_taken`，並告知被哪個料號占用。
- 搜尋排序與命中原因見 `docs/04` §4。
- 日後加條碼時，要重新檢討「精確識別碼」的統一管理（別名、料號、條碼）。
