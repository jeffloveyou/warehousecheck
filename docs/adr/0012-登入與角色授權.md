# ADR-0012：登入與角色授權（M1-03 提前的最小版本）

- 狀態：已接受（Accepted），使用者 2026-10-22 選擇「提前做最小登入」
- 相關：ADR-0003 D-12（Identity＋Cookie、無離線）、ADR-0010（共用 Data Protection 金鑰）、`docs/01` 角色、`docs/04` §3.9

## 背景
M1-03 是「物料 CRUD（含授權）」。授權需要知道使用者是誰，但完整的登入功能排在 M6-01。若先用假身分，M1 完成後系統仍無法實際使用，所以把最小登入提前到 M1-03。

## 決策
1. **ASP.NET Core Identity＋Cookie**，不使用 Identity UI 套件，登入、改密碼頁面自己寫（`Pages/Account`）。
   - 新增套件：`Microsoft.AspNetCore.Identity.EntityFrameworkCore` 10.0.4（MIT，Microsoft），版本與 EF Core 10.0.4 對齊。
   - Identity 表放在同一個資料庫、同一套 Migration：`users`、`roles`、`user_roles`、`user_claims`、`user_logins`、`user_tokens`、`role_claims`。
2. **三個角色**（固定 GUID 種子）：
   | 角色 | 能做什麼 |
   |---|---|
   | `SystemAdmin` | 預留給 M6（帳號、系統設定） |
   | `ItemManager` | 核准、退回、拒絕、停用物料；維護分類、單位 |
   | `Operator` | 查詢、提出物料 |
3. **授權政策**（`Warehouse.Api/Authorization/Policies.cs`）：
   - 預設政策：全站都要登入。
   - 不需登入的頁面與端點（明確開放）：登入頁、狀態首頁、`/Dev/*`（只在 Development 可用）、`/health/*`、`/api/system/info`。
   - `Items.Read`：任何登入者。
   - `Items.Submit`：Operator、ItemManager。
   - `Items.Review`、`MasterData.Manage`：ItemManager。
   - 資源層級的檢查在 Application 服務內做第二道，例如只有提出人能撤回。
4. **Cookie 與帳號安全**：
   - Cookie：HttpOnly、Secure、SameSite=Strict，8 小時滑動到期。
   - 連續 5 次密碼錯誤鎖 15 分鐘。
   - 密碼至少 8 碼，且至少 4 種不同字元，不強制大小寫或符號。
   - 每 5 分鐘重新驗證 security stamp：停用帳號、重設密碼後，舊 Cookie 會失效。
   - `/api` 未登入回 401、無權限回 403，不轉址。
5. **帳號建立用命令列**：`Warehouse.Web users create|reset-password|disable|enable|list`。
   - 初始密碼由程式隨機產生、只顯示一次，不經過命令列參數。
   - 第一次登入必須改密碼；改之前只能進改密碼頁，API 回 403。
   - 帳號管理畫面留到 M6-01。
6. **CSRF**：
   - Razor 表單使用內建 antiforgery。
   - `/api` 的 JSON 端點不另做 antiforgery。真正的防線是「寫入只收 `application/json`」（`JsonOnlyFilter`，其他類型回 415）加上「沒有開放 CORS」：跨站 HTML 表單送不出 JSON。
   - SameSite=Strict 只是輔助：它不看埠號，同一台主機上的其他網站仍算同站。
   - 日後若要開放 CORS 或新增非 JSON 的寫入端點，必須先重新評估 CSRF。

## 後果
- **A/B 切換不必重新登入**：Cookie 用 M0-12 的共用 Data Protection 金鑰加密，所以兩個槽位都能解開。
- **Secure Cookie 只能經 HTTPS 使用**：
  - 經代理（`X-Forwarded-Proto: https`）或 `localhost` 開發時正常。
  - 直接用 http 連槽位的內網 IP（例如 `http://192.168.0.86:5080`）**無法登入**。這是刻意的，正式環境一律經代理的 HTTPS。
- **部署新環境後要建立第一個管理員帳號**：用 `users create`，步驟見 `docs/04` §3.9。
- **M6-01 要補**：帳號管理畫面、稽核紀錄查詢、密碼政策設定、SystemAdmin 的實際權限。
- **舊版（M0-12）程式不受新表影響**：這次 Migration 只新增表與索引。
