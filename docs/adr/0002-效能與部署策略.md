# ADR-0002：低負載、Windows/NAS 部署與應用線上更新

- 狀態：提案（Proposed）
- 日期：2026-10-21
- 相關：`0001-技術基線.md`、`../10-低負載與跨平台部署.md`、`../11-線上更新與回滾.md`

## 問題
1. 客戶端包括低規格舊電腦，需要限制瀏覽器 CPU、記憶體及網路負載。
2. 正式主機可能是 NAS 或 Windows PC，NAS 型號未知，需規劃跨平台能力。
3. 要在正常應用程式更新時盡量不停止倉庫操作，避免庫存異動錯帳。

## 方案方向
- 前端優先輕量化，以 M0 實測決定 Razor Pages、Blazor 靜態 SSR 或其他方案。
- 後端保留 ASP.NET Core API + PostgreSQL。核心邏輯不得依賴 Windows-only 套件。
- 以 Windows PC、Linux x64 為首批部署對象，NAS 若為 ARM64 再補對應 PoC。
- 正式環境分離 App／設定／憑證／DB／附件；以反向代理提供固定內網 HTTPS URL。
- 優先 Blue-Green：兩套應用程式版本並行，readiness 通過才切流量，舊版排空後停止。
- PostgreSQL Schema 採 Expand → Migrate → Contract，維持 A/B 相容窗口；上線時人工控制 Migration。
- 對舊 PWA 資源與進行中的網頁表單提供相容期及安全更新提示。

## 明確非保證事項
- 單一 PC/NAS 的主機、電源、OS、反向代理或資料庫故障並非零停機；若要涵蓋需要額外 HA 架構。
- NAS 容器支援、CPU 架構、雙實例可用資源需硬體實測，不能以文件推定。
- 即使 App A/B 切換不中斷，破壞性 DB Schema 變更仍可能需要分階段部署或維護窗口。

## M0 裁決前的必要證據
- 低規格電腦硬體資訊及前端效能比較。
- Windows PC 與 Linux 代表環境可部署性；正式 NAS 的限制清單。
- 雙 App 實例的 CPU/RAM、健康檢查、請求切換及回滾示範。
- 庫存提交不中斷、不遺失、不重複的測試與可能限制。

## 後續
M0 完成後，補入測試設備、量測結果、批准人、日期及最終選型，再更改 ADR 狀態為 Accepted。未取得證據時保持 Proposed。
