# ADR-0018：盤點不凍結儲位、計數當下帳面與盤點調整單（M6-02）

- 狀態：已接受（Accepted），M6 計畫經使用者 2026-10-23 核准
- 相關：FR-06、ADR-0003 D-07、ADR-0004（負庫存與預留）、ADR-0014（庫存帳與過帳服務）、`docs/04` §22、`docs/05` T-M6-02-*

## 背景
FR-06 要求開立盤點、記錄實盤量、差異審核、產生調整單，並說「V1 優先採儲位凍結，或另行經 ADR 決議」。使用者 2026-10-23 決定：
- **不凍結**，以快照＋期間異動計算（現場盤點時照常進出倉）。
- 盲盤做成系統設定，預設開啟。
- 盤虧碰到預留時**允許調整**，「預留大於庫存」列入庫存異常。

## 決策
1. **資料**（Migration `M6_04_Stocktakes`，只新增）：`stocktakes`、`stocktake_locations`（範圍；`is_open` 部分唯一索引讓同一儲位同時只在一張未結束的盤點）、`stocktake_lines`（快照量、實盤量、計數當下帳面量、計數者與時間、待重盤）。`stock_documents` 類型加 `Adjustment`、明細加 `is_decrease`；單號 `ST-`、`ADJ-`（各自序列）。
2. **流程**：開始（倉庫主管，選全部或指定儲位）→ 盤點中（作業員、主管輸入實盤量；帳上沒有的物料新增「現場找到」行）→ 送審（每行都要有實盤量，0 也要填）→ 主管核准，或勾選行要求重盤 → 已核准／已取消。
3. **差異＝實盤量 − 計數當下帳面量**：
   - 開始時鎖範圍儲位 `FOR SHARE`（等進行中的過帳 commit）再由結存建快照。
   - 每次計數在交易內鎖盤點單 `FOR SHARE`、該盤點單的 advisory lock（同一張的計數排隊）、儲位 `FOR SHARE`，再讀此刻結存當作帳面量。過帳鎖儲位 `FOR UPDATE`，所以計數讀到的一定是「已提交的最新結存」。
   - 快照到計數之間的進出不會算成盤差；畫面另顯示「期間異動」（計數當下帳面 − 快照）。
4. **核准**（倉庫主管＋倉庫範圍＋冪等鍵＋xmin）：建立建立者與送審者預設不可自核（設定 `stock.stocktake.allow_self_approval`，D-07）。同一交易內建立 Adjustment 單（明細＝差異絕對值、`is_decrease` 表示盤虧）、批次建立新批號／序號，經 `IInventoryPostingService.ApplyAsync` 以**相對量**過帳（核准前後的其他異動不會被覆蓋），再把盤點單改為已核准、釋放儲位。
5. **盤虧不受預留限制**：`StockApplyOptions.IgnoreReservations`（只給調整單）跳過「扣除預留後的可用量」檢查；仍保留結存不可為負（trigger）、待驗不可為負、允許負庫存物料的全倉結存 ≥ −下限（不扣預留）。調整後可能出現預留大於庫存，列在庫存異常頁「預留大於庫存」。
6. **盲盤**（設定 `stock.stocktake.blind_count`，預設開）：盤點中，非倉庫主管在盤點畫面、盤點表、盤點匯出都看不到快照量、帳面量、差異與差異筆數（伺服器端就不回傳）。送審後結果公開。
7. **其他規則**：調整單只能由盤點產生（不能手動建立）、不能沖銷（盤點有誤就重新盤點）；盤點中的儲位不能停用；一張最多 2,000 行。

## 後果與限制
- 正確性依賴「點完一格立即輸入」：實際點數到輸入之間的進出，系統無法得知（畫面提示）。
- 盲盤只遮蔽盤點相關畫面：庫存查詢、異動歷史、結存匯出本來就顯示結存，盤點期間作業員仍看得到（使用者可再決定是否限制）。主管要求重盤時，作業員已看過送審後的差異，重盤不再是盲盤。
- **A/B 共存**：舊版（M6-02 之前）讀到 `Adjustment` 單據會在單據列表、異動歷史出錯。新版上線、舊版停掉之前不要核准盤點（`docs/11` §7.2）。開發機 `warehouse_dev` 目前不建立盤點資料（伺服器仍是舊版 A 槽位）。
- **鎖表容量**：核准時每個盤虧的料號＋倉庫一把 advisory 鎖，2,000 行最多約 2,000 把；目標 NAS／PC 要確認 `max_locks_per_transaction × max_connections` 足夠（`docs/09` 待辦，M7-01）。
- Migration Down 會刪除盤點三張表與 `is_decrease`（盤點歷史消失、盤虧數量的正負號遺失）；正式環境回滾不跑 Down（Up 是 Expand，舊版可帶著新結構運作）。
