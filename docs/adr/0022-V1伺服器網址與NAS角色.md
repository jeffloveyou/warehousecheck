# ADR-0022：V1 伺服器配置、代理與發布方式、網址、NAS 角色（D-17～D-20、D-22、D-27）

- 狀態：已接受（Accepted），使用者 2026-10-26 逐項決定
- 相關：ADR-0005（傾向 DB 獨立主機）、ADR-0008、ADR-0009、ADR-0010、ADR-0021、`docs/08`、`docs/10` §5、`docs/12`、`docs/13`

## 背景
上線前還有幾個部署決策沒有定案：
- D-20：資料庫和網站要不要放在不同主機。
- D-22：代理與發布方式。
- D-27：內網網域名稱。
- D-17～19：NAS 的機型、能力，以及能不能同時跑 A、B 兩個槽位。

V1 實際在一台 Windows 11 電腦上運作，網址是 `https://192.168.0.86:5443`。

## 決策
| 項目 | 決定 | 理由 |
|---|---|---|
| D-20 資料庫與網站 | **V1 放同一台**（PostgreSQL 17 與網站、代理都在正式伺服器上） | M0-13 實測：30 人時 A＋B＋代理＋PostgreSQL 約 0.5 GB；30 人負載 p95 約 57 ms（M7-11） |
| D-22 代理、服務、發布 | **照現行 Windows 做法定案**：<br>・YARP 反向代理<br>・A/B 兩個 Windows 服務（虛擬服務帳號）<br>・framework-dependent 發布<br>・`switch-release.ps1` 換版 | M0-12 起實測。M7-10 演練在負載中切換、回滾、故障注入都沒有遺失或重複扣帳 |
| D-27 網址 | **V1 繼續用 IP**：`https://192.168.0.86:5443` | 內網規模小，不需要另架 DNS。換 IP 的影響見「後果」 |
| D-17～19 NAS | 使用者的 QNAP（型號待查），**分兩個階段**：<br>① 先當外部備份目的地<br>② 再評估能不能把伺服器搬過去 | NAS 型號、CPU、RAM、能不能跑容器都還沒實機確認。AGENTS.md 第四節規定不能先假設 |

## 後果
- 單一主機是單點故障：
  - 電腦、硬碟、PostgreSQL 故障時系統停止。
  - 恢復要靠備份還原（RTO 4 小時，ADR-0021）。
  - A/B 只保證**換版**時不中斷，不是硬體高可用（AGENTS.md 第五節）。
- 在 NAS 階段 ① 完成之前，備份只在本機（ADR-0021 的限制）。
  - 程式已寫在分支 `feature/M8-04-nas-external-backup`：`set-backup-target.ps1`，可儲存 NAS 帳密並測試。
  - 使用者 2026-10-26 指示「NAS 的部分先跳過」，這個分支暫不合併。
  - 之後要由使用者先完成：在 QNAP 建立共用資料夾與專用帳號，並回報型號、CPU、RAM、QTS 版本、Container Station。之後再實測、合併。
- 階段 ② 的評估項目：
  - CPU 架構：x86-64，或 ARM64（需要 `linux-arm64`）。
  - RAM 能不能同時跑 A、B 兩個槽位。
  - PostgreSQL 要放在 NAS 還是留在 PC。
  - 程序依 `docs/13`。
- IP 改變時要處理三件事：
  - 伺服器憑證要重簽，讓 SAN 包含新 IP：`new-dev-certs.ps1 -IpAddress <新 IP>`，再用 `install-proxy.ps1` 換上新的 pfx。根 CA 沿用，裝置不必重新信任。
  - 各裝置的書籤或 PWA 要改成新網址。
  - 書面操作卡要更新。
  - 建議在路由器把伺服器設成固定 IP。要改用網域名稱時，再新增一份 ADR。
