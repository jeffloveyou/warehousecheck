# ADR-0030：公用帳號與操作人姓名

- 狀態：已接受（使用者 2026-11-16 核准）
- 日期：2026-11-16

## 背景
現場多人輪流使用同一台電腦或 PDA，需要多人共用的「公用帳號」。單據建立者（`stock_documents.created_by_name`）、過帳者（`stock_movements.actor_name`）、領用人（`recipient_name`）原本都取自登入帳號的顯示名稱，用公用帳號時分不出實際是誰操作的。

## 決策（使用者 2026-11-16 選擇）
1. **帳號旗標**：`users.is_shared`（預設 false），由系統管理員在帳號頁或命令列 `users create … --shared` 設定。登入時寫入 claim `warehouse:shared`；變更會換 security stamp，舊 Cookie 最慢 5 分鐘內失效。
2. **每次送出時選操作人**：公用帳號在快速進出結帳、購物車轉草稿、建立進出倉／移庫單，以及單據的確認、送審、核准、退回、取消、沖銷時，都必須選擇操作人。同一台裝置會帶入上次選的人（localStorage），可以修改；送出按鈕顯示姓名，避免換人時忘了改。
3. **從人員名單選**：新增主檔 `operator_names`（姓名 ≤30 字、去空白、不分大小寫唯一；不刪除只停用）。倉庫主管與物料管理員（`PartnersManage`）在 `/MasterData/Operators` 維護。伺服器只接受啟用中人員的 ID，不信任瀏覽器送來的姓名文字。
4. **併入現有姓名欄**：不新增欄位，紀錄寫成「王小明（倉庫公用）」（`Actor.WithOperator`；超過 100 字時截短括號內的帳號名稱）。單據列表、明細、列印、異動紀錄、Excel 匯出與姓名篩選全部自動生效。`Actor.Id` 仍是公用帳號本身。
5. **權限不另外限制**：公用帳號的角色照管理員設定。
6. **API 寫入拒絕公用帳號**：`/api/stock/documents` 的寫入端點遇公用帳號回 403 `user.shared_account_api`，因為 API 沒有選人步驟。讀取不受影響。

## 後果
- 自我核准檢查以帳號 Id 判斷：公用帳號建的單，同一個公用帳號（即使換了人）不能自己核准，除非系統設定允許自我核准。
- 購物車與個人常用設定仍以帳號為單位，用同一個公用帳號的人會看到同一批購物車（既有版本號可防止互相覆蓋）。
- 期初、盤點、物料建檔、關鍵字、預留等非進出倉動作，公用帳號仍只記帳號顯示名稱。
- **帶入上次選的人是取捨**（使用者選擇）：換人時沒改就送出，會記成上一位。用按鈕上的姓名提醒，伺服器分不出是這次選的還是帶入的。若現場常發生誤記，可改成不記憶或只在同一工作階段記憶（只改 `operator-picker.js`）。
- **生效延遲**：管理員把帳號改成公用或改回一般後，舊 Cookie 最慢 5 分鐘才換發；A/B 換版排空期間落在舊版的請求也不要求選人。這段期間只影響紀錄姓名，不影響庫存。要立即生效，請該帳號重新登入。
- 單據頁的確認、送審等動作的操作人由 `operator-picker.js` 補進表單，公用帳號在這些動作需要 JavaScript；沒有 JS 時伺服器會拒絕（安全失敗）。建單、轉草稿、快速結帳的選單在表單內，不受影響。
- 組合姓名是一般文字，日後若改成獨立欄位，需要另外做資料轉換（Expand → Migrate → Contract）。

## 相容與回滾
- Migration `M15_01_SharedAccounts` 只新增 `users.is_shared` 與 `operator_names`（Expand）。舊版程式不讀新欄位，可以在新結構上執行；回滾只切回舊版程式，資料表保留。
- 快速結帳的操作人放在查詢字串 `operatorNameId`，結帳 JSON 格式不變，與舊頁相容。
- 新版要先套用 Migration 才能啟動（登入會讀 `is_shared`）。
