# ADR-0029：作業草稿恢復與易用性

- 狀態：已接受（使用者核准 R1～R4 實作）
- 日期：2026-11-04

## 背景
快速進出已有交易冪等，畫面重載仍可能失去人工儲位、表頭與未知結果。庫存提示及日常維護入口分散，容易造成誤判。

## 決策
1. 保留 Razor Pages＋原生 JS，增加有界局部修改、帳號草稿與裝置 journal。每次加入、撤銷、結帳有各自識別碼，重試不改鍵。
2. 帳號草稿存 scan_carts nullable text，與 xmin 一起核對；裝置草稿版本過期需明確核對。草稿不預留、不入帳。
3. 在原結帳交易保存來源車＋操作者到單據的參照。恢復僅查本人結果；未知結果確認前不產生新結帳。
4. 搜尋點選完整規格，永久 ItemId 與料號一起核對。數量／條碼歧義由明確按鈕選擇；人工儲位不受後續掃碼覆蓋。
5. 撤銷只作用於未過帳車的指定增量，驗原 payload、版本與一次撤銷紀錄。庫存更正仍走既有單據。
6. 盤點背景保存絕對實盤量，有限逾時及未存提示，最後提交前核對最新差異。結存／預留／可出量分列，正式判定仍在過帳交易。
7. 標籤、完整錯誤報告與角色首頁沿用既有權限、編碼與資料。查詢分頁、報告串流，不加套件或輪詢。

## 2026-11-05 補充：依來源逐列恢復分配

- 儲位分配草稿保存來源快照，以購物車明細 ID 對應原 `LocationId` 及數量。即使倉庫相同、料號與數量相同，來源換位也視為該列變更。
- 來源變更時採目前清單的儲位和數量，並展示舊分配供核對。來源未變的列繼續恢復分配及未送總量。跨倉或舊格式來源無法確認時提示核對，再繼續作業。
- 目前儲位、裝置 journal 及已形成的原請求各自恢復。快速結帳結果不明時以原請求查詢或重試。新來源快照沿用現有草稿 JSON 欄位。驗收見05 T-QC-24／26，指令與結果見07。

## 2026-11-07 補充：同頁更新與焦點

- 用 Razor 同源回應中的具名區塊更新結果，查詢仍在伺服器分頁。只攔截明確標記的表單及分頁，失敗時保留目前的輸入與結果。瀏覽器返回與前進依查詢網址讀取對應結果。
- 草稿明細仍沿用原請求與佇列，焦點依目前操作位置還原。盤點背景儲存後可在原畫面重新讀取最新結果供核對。
- 回滾只需切回原應用程式資產和 Razor 頁面。此改動沿用既有資料結構與庫存交易。

### 表頭及常用維護表單

- 草稿表頭儲存後保留掃碼面板和明細輸入。只在回應確認同一筆提交的版本時同步單據動作。另一使用者先修改時，由操作者比對最新表頭後決定是否使用該版本重送。
- 物料索引、常用儲位與主檔以具名區塊更新。列上的操作保留其他表單草稿。表單仍走既有授權、驗證與稽核，保留原生提交入口。送審與過帳繼續依完整單據狀態重建畫面。

## 替代方案與後果
只做離頁警告不能處理當機或回應遺失；只存裝置不能跨裝置繼續。帳號草稿＋本機 journal 增加少量儲存與衝突處理，換取可恢復的輸入。裝置禁止儲存時必須明示並保護離頁，不宣稱支援離線庫存交易。

## 驗證與回滾
整合測試覆蓋擁有者、xmin、冪等、預留與查詢範圍；Chromium 109 驗證刷新、回應遺失與盤點保存。真機／現場效能獨立記錄。回退應用或關閉快速結帳，保留新增欄位及交易帳，不回退庫存。
