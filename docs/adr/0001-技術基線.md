# ADR-0001：技術基線（M0 待驗證）

- 狀態：提案（Proposed）
- 日期：2026-10-21

## 背景
混合型倉庫支援 Windows 舊電腦、手機、工業 PDA，正式伺服器可能是 Windows PC 或 Linux NAS。使用者希望 AI Agent 輔助開發且提供繁體中文開發手冊；依賴授權可商用、不強制付費的軟體。**新的低負載及不中斷更新需求，使前端技術不能在 PoC 前固定為 Blazor WebAssembly。**

## 保留的基線
- C# / .NET 10 LTS、ASP.NET Core Web API、PostgreSQL、EF Core/Npgsql。
- Modular Monolith；同一後端／資料庫供手機、PC 條碼槍、工業 PDA 使用。
- Web/PWA 介面、內網 HTTPS，V1 無離線庫存交易。
- 同一份跨平台程式碼，Windows PC／相容 Linux NAS 部署。

## 前端選項（M0 必須比較）
> 2026-10-21 更新：依 ADR-0005，M0 只完整比較選項 1 與 2；選項 3 只量測空白範本首次載入量作參考。
1. **Razor Pages + 精簡 JavaScript**：瀏覽器通常只需 HTML/CSS/JS，適合低規格客戶端，互動需額外實作。
2. **Blazor 靜態 SSR + 局部 JavaScript**：可使用 Razor 元件及伺服器渲染，需確認動態作業流程的複雜度。
3. **Blazor WebAssembly PWA**：前端 C# 便利，但首次載入瀏覽器執行環境，可能增加低規格客戶端負擔。

## 建議決策方式
M0 用相同核心流程（登入、查料、入庫表單、掃碼輸入）進行相近條件測試；記錄最慢電腦的初始載入、CPU/RAM、輸入反應及 PDA/手機相容性，經使用者批准後將本 ADR 改為 Accepted。

## 後果與限制
- 前端應優先低負載，而非一律採同語言 C#。
- 不論前端方案都須整合手機相機與 PDA/條碼槍鍵盤輸入。
- 若使用 Blazor 互動伺服器模式，更新版本時需另外處理長連線和 UI session，不能聲稱無感切換。
- 不中斷更新及雙平台部署的詳細決策見 `0002-效能與部署策略.md`。
