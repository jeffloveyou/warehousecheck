# ADR-0017：角色、帳號管理與依倉庫限制作業（M6-01）

- 狀態：已接受（Accepted），M6 計畫經使用者 2026-10-23 核准
- 相關：ADR-0012（登入與角色授權）、FR-07、`docs/04` §21、`docs/05` T-M6-01-*、T-M6-04-*

## 背景
ADR-0012 只做了最小登入：帳號由命令列建立，SystemAdmin 只能改設定，M1-03 審查 S3（登入時間差）延到 M6。docs/01 列出「只讀使用者」與「盤點審核者」。M6 要補齊帳號管理、操作日誌，並讓帳號只能在指定倉庫作業。

使用者 2026-10-23 的決定：
- 角色維持固定（寫在程式），新增 **Viewer（只讀使用者）**；盤差由倉庫主管核准，不另設盤點審核者；一人可多角色；不做畫面自訂權限矩陣。
- **V1 要依倉庫限制，但只限制作業、查詢不限**；未指定＝全部倉庫，既有帳號不受影響。

## 決策
1. **角色**：SystemAdmin、ItemManager、WarehouseManager、Operator、Viewer（`Roles.cs`，固定 GUID 種子，Migration `M6_01_ViewerRole` 只插入角色列）。Viewer 不在任何寫入政策內；沒有角色的帳號一樣只能查詢，但帳號管理畫面要求至少選一個角色，讓用途清楚。
2. **帳號管理** `/Admin/Users`（政策 `Users.Manage`＝SystemAdmin）：新增（隨機 12 字初始密碼只顯示一次、首次登入須改）、改名、多角色、停用／啟用、重設密碼、解除鎖定、倉庫範圍。畫面與命令列共用 `IUserAdminService`。
   - 每次變更更新 security stamp（已登入的 Cookie 最慢 5 分鐘內失效）；改自己時立即換發 Cookie。
   - 防呆：不能停用自己、不能拿掉自己的 SystemAdmin、至少保留一個啟用中的 SystemAdmin（鎖 roles 的 SystemAdmin 列 `FOR NO KEY UPDATE` 讓帳號寫入排隊）。
   - 每次寫入在交易內重查操作者「此刻仍是啟用中的 SystemAdmin」，避免被停用的管理員利用 5 分鐘空窗。
   - **被限制倉庫範圍的系統管理員不能做任何帳號管理寫入**：新帳號預設全部倉庫、重設別人密碼都能被用來繞過自己的範圍（M6-04 審查 R2）。
3. **登入**：帳號不存在或停用時也做一次密碼雜湊比對（關閉 S3 時間差）；成功、失敗、鎖定寫 `audit_logs`（操作者名稱固定「（登入）」；不存在的帳號只記前 2 字＋長度，因為常有人把密碼打進帳號欄）；同一 IP 每分鐘最多 `Login:RateLimitPerMinute` 次（預設 20），被擋時寫一筆警告日誌。
4. **倉庫範圍**：`users.all_warehouses`（預設 true）＋`user_warehouses`（Migration `M6_02_UserWarehouses`，只新增）。
   - 檢查在 Infrastructure 服務內、每次查資料庫（`WarehouseAccess.EnsureAsync`），權限變更立即生效，錯誤碼 `warehouse.forbidden`（403）。
   - 範圍：單據（建立、修改、送審、確認、核准、退回、取消、沖銷；移庫含目的倉）、期初單、手動預留、倉庫改名與啟停、新增倉庫（需全部倉庫）、儲位、倉位圖片、常用倉位、單據附件、盤點、匯入（儲位、期初明細）。
   - 單據類的檢查在版本比對之前：沒有權限的人一律得到 `warehouse.forbidden`，不洩漏版本資訊。
   - **不限制**：查詢（結存、異動、物料、匯出）；物料主檔工作（含負庫存設定，屬物料管理員的主檔工作）。
   - `Actor.Id = Guid.Empty`（命令列、背景工作）與資料庫找不到的 Actor 不受限。網頁與 API 的 Actor 一定來自登入 Cookie；**日後新增 API key、服務帳號等驗證方式時，必須改成「找不到帳號就拒絕」**。
5. **操作日誌** `/Admin/Audit`（政策 `Audit.Read`＝SystemAdmin）：期間必填（預設 7 天、最長 366 天）、計數上限 1 萬筆、可匯出。沒有新 Migration（沿用既有索引）。
6. **頁面層與服務層兩道檢查**：頁面 POST handler 一律先檢查政策（物料審核類 handler 在 M6-04 補上），服務層再檢查資源層級規則。M6-04 的授權掃描測試要求每個 handler 登記保護方式，並以每個不符合政策的角色直接 POST 驗證。

## 後果
- A/B 共存或回滾到 M6-01b 之前的版本時，舊版不執行倉庫範圍限制。上線切換時，新請求全部到新版、舊版停掉之後才開始設定倉庫範圍（`docs/11` §7.2）。
- 登入稽核量：每次登入一筆；`audit_logs` 尚無保留期限（`docs/09` 待辦）。
- 限流以來源 IP 分區：代理與網站不在同一台主機（例如不同容器）時要設定 `KnownProxies`／`KnownNetworks`，否則所有人共用代理 IP 的額度（`docs/10` §7）。
- 已知限制：帳號被鎖定時訊息不同，連錯 5 次可判斷帳號存在（已有 IP 限流，內網風險低）。
