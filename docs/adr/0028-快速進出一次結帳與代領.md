# ADR-0028：快速進出一次結帳與代領

- 狀態：已接受；使用者 2026-11-03 核准計畫並要求實作。
- 延伸 ADR-0026；保留一般單據、批號／序號及移庫的既有操作。

## 決策

1. 一般物料可在購物車同頁掃碼、拆分實際儲位數量、核對後一次進貨或領料。購物車本身不動庫存、不預留；同車同一來源倉庫。
2. 審核關閉時直接過帳；開啟時送審並依既有規則建立預留。送審不能顯示為已入帳；不變更主管核准及自核規則。
3. 操作帳號與領用帳號分開：領用人預設本人，可選其他啟用帳號。只限制操作人的倉庫權限，領用人無須有作業權限。結帳時再次檢查帳號啟用。
4. 單據新增 nullable 的領用帳號、領用名稱快照及專案／工單（最多100字）。歷史資料不回填推定值；沖銷單保留來源的追溯欄位。購物車備註帶入單據，仍尊重既有表頭欄位設定。
5. 沿用 `scan_carts.xmin`，每次明細修改確保父列 UPDATE。修改數量、刪行及結帳核對預期版本；新增累加以鎖與操作識別碼依序處理。
6. 掃碼加入與結帳使用 `processed_commands`：鍵前綴區分命令、請求 SHA-256 包含擁有者及完整資料；同鍵同內容回傳既有結果，不同內容拒絕。鍵鎖、業務修改與命令紀錄同一交易，受既有冪等紀錄保留期限約束。
7. 一次結帳在同一交易鎖購物車、核對版本／分配／權限／表頭、建單、沿用過帳或送審服務、寫稽核、刪車。任何失敗整批回滾。不得串接已各自提交的公開建單與確認方法。
8. 手動數量等待不釋放佇列，相機暫停辨識；收到的後續掃碼保留。失敗或結果不明保留可重試／略過紀錄，處理前不得結帳。結帳期間及結果不明時凍結原內容，重試同一操作。
9. 前端局部回應帶修改前後版本；版本缺口重新讀取一致快照。預檢以版本、倉庫及查詢序號判斷過期；其資料不構成預留或出庫承諾。
10. `stock.documents.quick_checkout_enabled` 預設 true，可在設定頁關閉，恢復轉草稿入口；掃碼防漏修正繼續保留。不新增套件或離線交易。

## 相容與後果

- Migration 只新增可空欄位、索引及領用帳號 Restrict 外鍵；舊版仍可讀寫原欄位。
- 舊加入回傳 HTML 與轉草稿入口保留；新局部加入使用獨立AddDelta handler且需操作識別碼，避免降版誤走無去重的舊加入。原服務呼叫的可選參數保留相容性。
- 領用帳號查詢限作業權限與自己的購物車，只傳 ID、帳號、顯示名稱，最多20筆。
- 倉庫可用量沿用正式過帳的 SQL，來源結存與倉庫預留分開顯示；每料最多列20個有效來源，其他可用儲位選單查詢。
- 回滾關閉新入口或回到舊版應用，保留新欄位與既有單據。不執行 Migration Down 刪除追溯資料。
- 開發機自動化測試不能取代 Android／iPhone 及低規格實機驗收；實際證據見開發日誌及驗收測試。

## 2026-11-06 補充：以確認時顯示的審核模式為準

- 快速結帳帶上畫面所顯示的審核模式。實際設定已切換或舊頁未提供模式時，先停止本次新結帳，保留購物車並請操作者重新整理核對。已成功的原請求仍依原鍵查回。
- 新頁使用獨立 CheckoutReviewed 入口，避免舊服務接收新版請求卻略過模式核對。見開發手冊 §28.2 與線上更新手冊。
