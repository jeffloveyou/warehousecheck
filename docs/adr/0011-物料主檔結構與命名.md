# ADR-0011：物料主檔結構、申請單號與正式料號分離、資料庫命名

- 狀態：已接受（Accepted），M1-01 計畫經使用者核准；2026-10-21
- 相關：ADR-0003（D-01、D-02、D-06）、ADR-0004、ADR-0006、`docs/02`、`docs/04` §3

## 背景
M1-01 建立第一個 Migration。之後改結構都要走 Expand → Migrate → Contract，所以命名規則、物料識別碼與狀態要先定好。

## 決策
1. **資料庫命名 snake_case**（使用者選擇）：`items`、`item_code`、`ck_items_status`。以 `EFCore.NamingConventions` 10.0.1（Apache-2.0）在 `WarehouseDbContext.OnConfiguring` 套用，C# 仍用 PascalCase。理由：手寫 SQL／psql 查詢不需雙引號。例外：EF 的 `"__EFMigrationsHistory"` 表名維持預設（欄位為 snake_case）。
2. **三種識別碼分開**（使用者 2026-10-21 補充要求）：
   | 欄位 | 何時產生 | 用途 | 規則 |
   |---|---|---|---|
   | `id`（UUID） | 建立時 | 所有關聯鍵 | 永久不變 |
   | `request_no`（`MR-000125`） | 作業員提出時 | 查詢、追蹤、審核 | 唯一、必填、永久保留，核准後不消失 |
   | `item_code`（`EL-000125`） | 物料管理員核准時 | 正式業務識別 | 唯一；核准前為 NULL；發放後不得重新分配 |
   退回、拒絕、判定重複都不占用正式料號。
3. **狀態** `PendingApproval`、`Returned`、`Rejected`、`Active`、`Inactive`，以文字儲存（psql 可直接讀）。CHECK：`Active`／`Inactive` 必有料號；其他狀態一定沒有。只有 `Active` 可交易（ADR-0003 D-02）。
4. **雙重保護**：Domain 實體檢查必填、長度、格式、負庫存規則（丟 `DomainRuleException`）；資料庫以 CHECK、唯一索引、外鍵 RESTRICT 再保證一次，避免手寫 SQL 或日後程式錯誤繞過。
5. **料號不重新分配**：唯一索引＋trigger `trg_items_protect_item_code`（已發放料號不可變更、清除，有料號的物料不可刪除）＋產生器只遞增（M1-02）。格式 CHECK：`MR-` 至少 6 位數、料號 2～4 碼前綴＋至少 6 位數；料號前綴在分類間唯一。
6. **數量** `numeric(19,4)`；單位小數位數 0～4。
7. **樂觀併發**用 PostgreSQL 系統欄位 `xmin`（不另建版本欄位）。
8. **內建資料**（8 個單位、6 個頂層分類）以固定 GUID 寫在 Migration；之後修改須另一個 Migration。

## 後果
- M1-02 要新增：申請單號／料號產生器（併發唯一）、審核紀錄表、核准時重複檢查；都是新增表／欄位（Expand），與 M1-01 相容。
- 物料專屬單位換算、建立者欄位、別名與關鍵字皆以後續 Expand Migration 加入。
- 已發布的 Migration 檔不得修改；結構調整一律新增 Migration。M1-01 本身因審查補強而有兩個 Migration（`M1_01`、`M1_01b`）。
- `Down` 僅供開發／測試；正式環境回滾保留資料表、只切回舊版程式。
- 時間一律以 UTC 儲存（Domain 轉換）；顯示時才轉當地時間。
- 新增狀態值時，必須先發布能讀取新值的版本、確定不回滾後才寫入新值。
- `SeedData` 只能新增項目，不能刪改既有項目。
