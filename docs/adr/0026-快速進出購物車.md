# ADR-0026：快速進出（先掃碼成購物車，再整批選進倉／出倉／移庫）

- 狀態：已接受（Accepted），使用者 2026-10-31 核准
- 相關：ADR-0014（庫存帳保護）、ADR-0015（進出倉單）、ADR-0016（掃碼）、ADR-0024（帳號常用設定）、`docs/04` §17.6、`docs/11` §7.6

## 背景
原本的進出倉流程是：
1. 先選類型、倉庫、用途，建立草稿。
2. 到明細頁掃碼。
3. 確認過帳。

使用者要多一個模式：現場先把一批料掃起來，掃完再決定整批是進倉、出倉還是移庫。

## 決策
1. **入口**：新增「快速進出」頁（`/Quick`），原本的進出倉單流程不變。權限與進出倉單相同（`DocumentEdit`）。
2. **購物車**：
   - 存在新資料表 `scan_carts`、`scan_cart_lines`，記在帳號（換手機、關瀏覽器都還在）。
   - 一個帳號可以有多台購物車；只有擁有者看得到、改得了（倉庫主管也看不到別人的）。
   - 名稱用建立時間，可以加備註。
   - 購物車只是清單：不動結存、不預留、不寫稽核。
   - **放棄購物車是實體刪除，不留紀錄**（使用者決定）。
3. **掃碼階段**：
   - 先掃物料或儲位都可以，記錄物料、數量（基本單位）、儲位（可空）。
   - 掃了儲位 QR 之後，再掃的物料都記在這個儲位。
   - 同一物料＋同一儲位會合併數量。
   - 有儲位的行一律在同一個倉庫（購物車「鎖定」倉庫）；只有儲位碼時要先有倉庫，否則請掃儲位 QR。
4. **選動作與補齊**：
   - 整批一次選進倉、出倉或移庫，同時選倉庫與用途，預設都是上次用的（`documents.lastWarehouse`、`quick.lastPurpose.in/out`）。
   - 缺儲位的行在補齊畫面補上。儲位選單裡，有這個料的儲位排前面、數量少的最前面，並顯示數量（進、出、移都一樣）。
   - 移庫的目的儲位每行各自指定；批號物料填批號；序號物料要填等於數量的序號個數，每個序號成為一行。
5. **轉單**（`IStockDocumentService.CreateFromScanCartAsync`）：
   - 在同一個交易裡完成三件事：建立草稿、逐行套用與手動加行**同一份規則**（`AddLineCoreAsync`）、刪除購物車。
   - 任一行不合規則就整批不轉，購物車保留。
   - 新單據 ID 由畫面產生（RequestId），重送回傳同一張。
   - 之後到既有單據頁核對、可以再加掃，確認過帳；開啟主管核准時改為送審（沿用 D-26）。
6. **刪除購物車草稿**：
   - 從購物車轉入的草稿（`stock_documents.from_scan_cart`）不要了，可以直接刪除，不留單據（單號會跳號）。
   - 只限草稿、建立者或倉庫主管，而且沒有附件、從未送審（曾送審退回的單有退回意見與審核紀錄，保留歷史，請改用取消）。
   - 稽核紀錄保留：查得到誰在何時刪了哪個單號，以及原本的明細（料號、儲位、批號／序號、數量）。
   - 資料庫 trigger `stock_documents_protect()` 只放寬這一個例外；其他單據一律不可刪除。`from_scan_cart` 只在建立時決定，之後不可修改（trigger 擋）。

## 後果
- 好處：
  - 現場可以先掃再決定用途。
  - 轉單規則與手動建單完全相同，庫存正確性不受影響：仍然只在確認過帳時由 `InventoryPostingService` 異動。
- 代價：
  - 多兩張表與一個 Migration（只新增，換版可以不停機，見 `docs/11` §7.6）。
  - 單號可能跳號：刪除的草稿，以及轉單失敗時已取的號碼。
  - 購物車內容在轉單前不檢查庫存是否足夠；確認過帳時才檢查。
- 已知限制：
  - 掃碼階段「自動」與「逐件累加」相同：同料同儲位一律合併，所以只提供「手動」與「自動」兩種。
  - 序號物料出倉時，序號要自己輸入，沒有從現有序號清單點選。
