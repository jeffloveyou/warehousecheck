# ADR-0014：庫存帳模型與過帳服務（M3-03）

- 狀態：已接受（Accepted），M3 計畫經使用者 2026-10-22 核准
- 相關：AGENTS.md 第六節、ADR-0003（D-05～D-07）、ADR-0004、`docs/02`、`docs/04` §14

## 背景
期初建帳是第一次真正寫入庫存。之後 M4 的入庫、出庫、移庫、預留都建立在同一套結存與異動帳上，所以資料結構與「誰能改結存」要先定好。

## 決策
1. **四張帳**：
   - `stock_documents`／`stock_document_lines`：單據，目前只有期初；M4 加入其他類型。
   - `stock_balances`：即時結存，維度是物料＋儲位＋批號＋序號＋狀態。
   - `stock_movements`：異動帳，只能新增。
   - 另外有：`inventory_lots`（批號，含有效期限）、`item_serials`（序號）、`processed_commands`（冪等鍵）。
2. **單一入口**：
   - 只有 `IInventoryPostingService.ApplyAsync`（`Infrastructure/Inventory/InventoryPostingService.cs`）會寫 `stock_balances`。
   - 必須在呼叫端的交易內執行。每筆變化：
     1. upsert 結存：`INSERT … ON CONFLICT (維度) DO UPDATE SET quantity = quantity + 變化 RETURNING`。
     2. 寫一筆異動：數量變化、異動後結存、操作者、時間。
3. **資料庫保證**：
   - 結存唯一：`ux_stock_balances_dimension`，以 `NULLS NOT DISTINCT` 處理 NULL 的批號與序號。
   - 序號唯一：
     - `ck_stock_balances_serial_quantity`：序號結存只能是 0 或 1。
     - `ux_stock_balances_serial_in_stock`：同一序號只能有一處數量大於 0。
   - 不可為負：`ck_stock_balances_non_negative`。M4 導入負庫存例外時，會改成依物料設定檢查（ADR-0004）。
   - 異動帳：trigger 禁止 UPDATE、DELETE、TRUNCATE。
   - 單據：不可刪除；已過帳或已取消的不可修改；明細只能在草稿時修改，送出後只允許過帳流程填入 lot_id／serial_id。
4. **冪等**：
   - 核准需要冪等鍵（網頁表單的隱藏欄位，API 的 `Idempotency-Key` 標頭）。
   - RequestHash 是「命令類型＋單據 ID＋讀取時的版本＋操作者」的 SHA-256。
   - 判斷規則：同鍵同內容，回傳成功、不再過帳；同鍵不同內容，回 `idempotency.key_reused`。
   - 冪等紀錄和過帳在同一交易寫入；鎖住單據後會再查一次，兩個同鍵請求同時送達也只會過帳一次。
5. **鎖順序**（避免互相等待）：
   1. 單據 `FOR UPDATE`。
   2. 儲位依 id 排序 `FOR UPDATE`。
   3. 倉庫 `FOR SHARE`。
   4. 批號、序號：依（物料, 號碼）排序後 upsert。
   5. 結存列（由 upsert 鎖住）。
   - 交易內 `SET LOCAL lock_timeout = '5s'`。死結、序列化失敗、等鎖逾時都轉成「請稍後再試」（`opening.busy`），交易回滾、不會錯帳。
   - 停用倉庫或儲位前，先 `FOR UPDATE` 鎖住該列再查結存：正在過帳的交易 commit 後才檢查，看得到剛寫入的結存。
6. **期初規則**：
   - 每個儲位只能做一次期初（`locations.opening_document_id`）；之後的更正走 M6 的盤點或調整單。
   - 「確認為 0」寫成沒有物料的明細，該儲位會標記為已清點。
   - 期初結存一律寫 `Available`；可用與否由儲位目前狀態決定（決策 7），儲位改回有效後就能使用，不會卡在待驗。
   - 自核規則依 D-07 設定。
7. **可用量**：
   - 結存狀態是 Available，**而且儲位目前是有效（Available）**，才算可用。
   - 儲位改成待驗後，原有結存立即不算可用，不需要另外搬帳。
   - 有庫存的儲位或倉庫不能停用（M3-01 審查 #3）。
   - **M4 的可用量 SQL 必須同時符合 `stock_balances.stock_status = 'Available'` 與 `locations.status = 'Available'`**（ADR-0004 的公式依此解讀）。
   - `Quarantine` 保留給日後「單筆結存待驗」的流程（例如進貨檢驗），M3 不寫入。

## 後果
- M4 在 `InventoryPostingService` 加上「扣減」：條件式更新，加上可用量、預留、負庫存下限的檢查，都在同一交易內完成。
- 錯帳只能用新的單據更正，不刪改異動帳，稽核軌跡完整。
- `Down` 會刪除全部庫存帳，只用於開發／測試環境。
