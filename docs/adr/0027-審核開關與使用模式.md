# ADR-0027：審核開關與使用模式（物料、期初、盤點可不審核）

- 狀態：已接受（Accepted），2026-10-31 計畫核准後實作；本文依實作整理，2026-11-02 使用者確認內容
- 相關：ADR-0003 D-07（自核）、ADR-0011（物料審核）、ADR-0015（進出倉單審核 `stock.documents.approval_enabled`）、ADR-0018（盤點、盲盤）、ADR-0023（自動核准）、`docs/04` §26

## 背景
原本物料建檔、期初單、盤點差異一定要主管核准；只有進出倉單可以關閉審核。
小公司只有一兩個人管倉庫，每一步都要「送審 → 換人核准」很麻煩，自核又要另外開。
使用者要能依公司規模選擇審核的嚴格程度。

## 決策
1. **三個新開關**（`system_settings`，預設都開啟，所以升級後行為不變）：
   - `items.approval_enabled`：物料建檔要物料管理員核准。
   - `stock.opening.approval_enabled`：期初單要倉庫主管核准。
   - `stock.stocktake.approval_enabled`：盤點差異要倉庫主管核准。
   - 只有存成 `false` 才算關閉；沒有這筆設定等於開啟。不需要 Migration。
2. **物料審核關閉**：
   - 提出即核准、發正式料號（`ItemWorkflowService.SubmitAsync` 帶選項的版本；網頁、API、Excel 匯入都走這條）。
   - **疑似重複的維持待核准**，交給物料管理員判斷；只有物料管理員提出時確認過的候選算數，作業員勾選的不算。
   - 與「自動核准」共用同一把排隊鎖與同一個查重條件，兩人同時提出同名物料也只會有一個直接啟用。
3. **期初審核關閉**：草稿上按「確認過帳」（`IOpeningService.ConfirmAsync`），建立者或倉庫主管都可以。
   - 過帳步驟與核准完全相同（同一段程式），只差狀態檢查與權限；冪等命令名稱 `opening.confirm`，與核准分開。
   - 審核關閉時「送出核准」被拒（`opening.approval_disabled`）；審核開啟時「確認過帳」被拒（`opening.approval_required`）。
4. **盤點審核關閉**：盤點中按「確認盤點」（`IStocktakeService.ConfirmAsync`）＝送審＋核准，記為同一人。
   - 送審的檢查照舊（都已盤點、沒有待重盤），有差異就產生調整單並過帳；冪等命令名稱 `stocktake.confirm`。
   - 確認要帶開頁時的**計數戳記**（行數、已盤行數、待重盤行數、最後計數時間）：計數不會改表頭版本，開頁後有人改了實盤量就拒絕（`stocktake.counts_changed`），避免過帳確認者沒看過的差異。
   - 稽核只有一筆 `stocktake.confirm`（另有調整單過帳的稽核），送審者與核准者記同一人。
   - 錯誤碼 `stocktake.approval_disabled`／`stocktake.approval_required`。前置檢查被拒（開關、戳記、還沒盤完）不寫過帳失敗紀錄；進入調整單過帳後的失敗才寫。
   - **不套用盲盤**（`SystemSettings.EffectiveBlindCount`）：沒有主管把關差異，確認前要看得到帳面量。盲盤設定本身保留，重新開啟審核就恢復。
5. **切換時已在流程中的單據**：已送審（待核准）的物料、期初單、盤點單，關閉審核後仍由主管核准，不檢查目前的開關。
   - 設定切換當下正在處理的請求，依讀到的值處理；物料提出在取得排隊鎖後再讀一次設定。
6. **使用模式**（`UsageModes`）：設定頁上的捷徑，一次設好 8 項審核相關設定，本身不存成設定。

   | 項目 | 簡易（小公司） | 標準（＝系統預設） | 嚴格 |
   |---|---|---|---|
   | 物料、期初、盤點要審核 | 否 | 是 | 是 |
   | 進出倉單要審核 | 否 | 否 | 是 |
   | 三種自核（期初、盤點、進出倉單） | 允許 | 不允許 | 不允許 |
   | 盲盤 | 否 | 是 | 是 |

   - 按「套用」只把值填進表單、不儲存，管理員確認後按「儲存」才生效（照常做衝突檢查、寫稽核）。
   - 目前設定剛好符合哪個模式就顯示名稱，逐項調整過就顯示「自訂」。

## 後果
- 好處：小公司不必換人核准就能作業；大公司維持原樣或改嚴格。
- 代價：關閉審核後，過帳只靠操作者本人；稽核紀錄照樣記錄誰在何時確認（`opening.confirm`、`stocktake.confirm`、物料審核紀錄「物料審核已關閉，提出即啟用」）。
- 庫存正確性不受影響：仍然只由 `InventoryPostingService` 在同一交易內異動，冪等與鎖與核准相同。
- 已知限制：
  - API 目前只有期初「核准」端點，沒有期初、盤點的「確認」端點（網頁可用）。
  - 模式只包含審核相關設定；欄位開關、保留期限等不在模式內。
  - 期初「確認過帳」沒有計數戳記：確認前另一位可編輯者（建立者或倉庫主管）加的行會一起過帳。可編輯的人本來就有限，先不處理。
  - 物料審核關閉後，每次提出物料都排同一把排隊鎖；大批 Excel 匯入期間，其他人提出物料要等匯入完成。
