# 待決事項與決策清單

**原則：** 以下事項目前尚未由使用者明確決定，AI Agent 不得將預設假設寫成已批准規格。能先做不受影響的小步 PoC 時，不要阻擋整個專案。

| ID | 待決問題 | 建議預設 | 最晚決定階段 |
|---|---|---|---|
| D-01 | 正式料號是流水號、分類前綴或保留既有外部編碼？ | 內部唯一 ID + 人類可讀料號，先用類別前綴示範；規則可設定 | M1 |
| D-02 | 正式物料誰可以建檔？ | 一般員工提出、物料管理員確認 | M1 |
| D-03 | 專屬別名能否自由新增？ | 先需檢查衝突並由指定角色核准；共用關鍵字直接新增 | M2 |
| D-04 | 物料規格欄位及圖片是否必填？ | 最小必填料號、品名、單位、類別；其他可後補 | M1 |
| D-05 | 儲位命名、同儲位混放及負庫存規則？ | 允許混放、負庫存禁止 | M3 |
| D-06 | 批號/序號哪些分類必填？ | 依每個料號獨立設定 | M1/M3 |
| D-07 | 期初建帳與盤點由誰核准？ | 物料管理員／盤點審核者 | M3/M6 |
| D-08 | PDA 品牌、型號、Android 版本與條碼碼制？ | 先以 Keyboard Wedge 測試，實機確定 | M0/M5 |
| D-09 | HTTPS 憑證、內網網域與伺服器 OS？ | 公司可控內網 DNS + 受裝置信任憑證 | M0/M7 |
| D-10 | 日常使用者數、料號量、單據量、查詢效能目標？ | M0 調查，M2 前定量 | M2 |
| D-11 | 庫存保留與進階採購／工單整合是否在 V1？ | 不阻擋 V1，需求成立後增補 | M1 |
| D-12 | UI 畫面、登入方式及離線需求？ | 先不做離線交易、採官方身分驗證方案 | M0/M5 |
| D-13 | 備份 RPO/RTO 與資料保留年限？ | 上線前由公司負責人核准 | M7 |
| D-14 | 使用哪個 IDE、Git 遠端與 Agent 工作方式？ | Windows + PowerShell、Git、本地編輯、小步核准 | M0 |

| D-15 | 最低規格 Windows 電腦的 CPU、RAM、OS 及瀏覽器？ | M0 現場清查及量測 | M0 |
| D-16 | Razor Pages、Blazor 靜態 SSR 或 WASM 哪個最輕？ | 依 M0 PoC 測試結果批准 | M0 |
| D-17 | NAS 品牌、型號、CPU（x64/ARM64）、RAM、OS？ | 未確認前不得宣稱 NAS 兼容 | M0/M7 |
| D-18 | NAS 能否安裝相容容器及持久化 PostgreSQL？ | 優先驗證容器／權限／空間；不強制同機 DB | M0/M7 |
| D-19 | NAS/PC 能否同時執行 App A/B 兩份實例？ | M0 量測 RAM、CPU、埠與代理切換 | M0 |
| D-20 | 正式 DB 要與 App 同機或另外架設？ | 依現有資源、備份與可用性要求確認 | M0/M7 |
| D-21 | 「不中斷」可接受的失敗率、等待時間及維護限制？ | 先以正常應用更新接近零中斷為目標 | M0 |
| D-22 | Windows/NAS 各採何種代理、服務管理與發布方式？ | 以同一程式碼與不同部署設定為原則 | M0/M7 |
| D-23 | 新舊 Web/API/PWA 的相容期間與安全更新提示方式？ | 覆蓋 A/B 共存與舊頁面存續窗口 | M5/M7 |
| D-24 | 最低效能標準、測試資料量與同時使用者數？ | 由 M0 記錄測試條件並核准基線 | M0/M2 |

每個決議請新增或更新 ADR，寫出：背景、選項、決定、後果、批准日期。
