# 維護知識與交接說明（不含練習題）

## 目的
希望人類維護者最終能靠文件理解、修改及發布系統；因此 AI Agent 必須把程式位置、修改原理、常見故障、測試指令留下來。**本專案不安排練習題、課後作業、指定獨立修改任務或畢業考核。**

## 每個功能的知識交接標準
1. 功能入口在哪個畫面或 API。
2. UI → API → Application → Domain → Infrastructure → Database 完整資料流。
3. 需要修改的實際檔案、類別及方法，與修改理由。
4. 可能破壞的資料庫約束、角色權限與併發規則。
5. 可複製的 PowerShell 驗證命令、預期及真實輸出。
6. 相關測試路徑、常見例外訊息及排錯順序。
7. 對應 Git commit、發版與回滾方法（如適用）。

## AI Agent 與使用者合作方式
- Agent 每次先提供修改計畫供使用者核准，再在核准範圍內修改程式。
- 使用者可選擇自己修改或交給 Agent 實作；無需完成任何教學題。
- 開發機上的 `dotnet`、開發 DB、測試、git 等指令由 Agent 直接執行，並在 `docs/07-開發日誌.md` 留下「指令、實際結果、學習重點」歷程（使用者 2026-10-21 指示，見 AGENTS.md 第一節）；正式環境部署與正式資料庫 Migration 仍須使用者同意。
- 沒有執行過的命令、沒有實機完成的部署，不得寫成已驗收。

- DISM 啟用 `Microsoft-Windows-Subsystem-Linux`、`VirtualMachinePlatform`（需重開機）；winget 安裝 WSL 2.7.13。
- `%USERPROFILE%\.wslconfig`：`networkingMode=mirrored`（Linux 的 localhost＝Windows 的 localhost）。
- 程式：`AddSystemd()`（`Microsoft.Extensions.Hosting.Systemd` 10.0.13）；`src/` 靜態檢查無 Windows-only API。
- `scripts/linux/install-service.sh`、`uninstall-service.sh`（可執行位元已設）、`deploy/docker/Dockerfile`、`.dockerignore`。

### M0-11 下一步（依序）
1. 確認 `wsl --status` 正常 → `wsl --install -d Ubuntu-24.04 --no-launch`（若需建立 Linux 帳號，請使用者在跳出視窗輸入一次）。
2. 確認 Ubuntu 已啟用 systemd；安裝 .NET SDK 10（`dotnet-install.sh`，裝到 `/usr/share/dotnet` 並連結 `/usr/bin/dotnet`）、Docker Engine（Docker 官方 apt 套件庫）、`bc`、`curl`。
3. Ubuntu 內 `git clone /mnt/c/CodeProject/物料管理系統 ~/warehouse`，切到 `feature/M0-11-linux`，`dotnet build`、`dotnet test`（`WAREHOUSE_TEST_DB` 指向 `localhost`）。
4. Windows 上 `.\scripts\publish.ps1 -Runtime linux-x64` → Ubuntu 內 `sudo ./scripts/linux/install-service.sh --release <路徑> --connection-string-file <暫存檔> --verify-restart`；驗證 ready、版本、`journalctl`、記憶體；之後 `uninstall-service.sh`。
5. Docker：建置映像、`--network host` 執行、ready 200、映像大小與 `docker stats`。
6. linux-arm64：發布 arm64、`tonistiigi/binfmt` 安裝 QEMU、`--platform linux/arm64` 嘗試執行（標示「模擬」）。
7. 文件：`docs/04` §11、新增 `docs/adr/0009-Linux部署與容器.md`、`docs/10` §6、`docs/05` T-M0-11-xx、`docs/07` 歷程、`docs/09` 勾選 M0-11、README；開 PR，合併前問使用者。
8. 完成後刪除本節與記憶 `m0-11-reboot-handoff`。
