# 維護知識與交接說明（不含練習題）

## 目的
希望人類維護者最終能靠文件理解、修改及發布系統；因此 AI Agent 必須把程式位置、修改原理、常見故障、測試指令留下來。**本專案不安排練習題、課後作業、指定獨立修改任務或畢業考核。**

## 查閱路線
| 模組 | 手冊應提供的內容 | 對應里程碑 |
|---|---|---|
| C# / .NET / Git | Solution 與 Project 依賴、NuGet、PowerShell、commit 與回退 | M0 |
| 物料建檔 | Entity／DTO、唯一料號、EF Core Migration、授權與測試 | M1 |
| 別名搜尋 | `ItemAliases`、`ItemKeywords`、正規化、LINQ、索引與分頁 | M2 |
| 倉庫與期初建帳 | 儲位、批號、序號、建帳單、庫存歷史 | M3 |
| 庫存交易 | Transaction、鎖、冪等、併發與回滾、除錯方式 | M4 |
| 網頁與掃碼 | 渲染方案、PWA、相機權限、HID/PDA 焦點與掃描流程 | M5 |
| 權限與盤點 | 登入、授權、稽核、盤點差異與審核 | M6 |
| 效能與部署 | 瀏覽器 CPU／RAM、API/DB 查詢、Windows/NAS 發布及故障診斷 | M0–M7 |
| 線上更新 | Blue-Green、readiness、流量切換、資料庫相容及版本回滾 | M0–M7 |

## 每個功能的知識交接標準
1. 功能入口在哪個畫面或 API。
2. UI → API → Application → Domain → Infrastructure → Database 完整資料流。
3. 需要修改的實際檔案、類別及方法，與修改理由。
4. 可能破壞的資料庫約束、角色權限與併發規則。
5. 可複製的 PowerShell 驗證命令、預期及真實輸出。
6. 相關測試路徑、常見例外訊息及排錯順序。
7. 對應 Git commit、發版與回滾方法（如適用）。

## AI Agent 與使用者合作方式
- Agent 每次先提供修改計畫供使用者核准，再在核准範圍內修改程式。
- 使用者可選擇自己修改或交給 Agent 實作；無需完成任何教學題。
- `dotnet`、DB Migration、正式發布原則上由使用者親自執行；Agent 必須解釋指令及分析輸出。
- 沒有執行過的命令、沒有實機完成的部署，不得寫成已驗收。

## 完成交接的認定
以文件準確、版本對應、功能驗證及部署可重現為準；不以測驗、練習題或口頭考試為驗收條件。
