# 快速進出換版與試運轉

本包適用 Windows x64 Framework-dependent，沿用正式主機既有的 .NET 10、A/B 槽位與反向代理。包名、來源 commit 和前一包見包內「換版說明.json」。本次加入單據先填數量再掃碼、草稿明細直接改量、同頁查詢與常用維護，並補強送審前的明細核對及盤點狀態同步。

## 換版步驟

1. 將完整 ZIP 複製到正式主機或隨身碟，解壓縮到獨立資料夾。
2. 在該資料夾雙擊「一鍵換版.cmd」，依畫面核對版本與換版包來源。
3. 確認備份成功後繼續。程式會校驗檔案、列出正式資料庫尚缺的 Migration，套用後啟動待命槽位，通過 readiness 再切換。
4. 瀏覽器完成目前作業後重新整理；PWA 如顯示新版提示，完成未送出的作業後再更新。

換版工具會要求正式主機的確認，本包沒有連線更動正式主機。不要只複製 DLL，也不要修改解壓縮後的腳本或發布檔，否則 SHA256SUMS 校驗會失敗。

## 資料庫相容性

本次相較前一個試運轉包沒有新增 Migration。從較早版本更新時，換版工具仍會依正式主機的資料庫紀錄列出待套用項目。

- `20261103105851_M13_01_QuickCheckout`：單據新增可空的領用帳號、領用名稱快照與專案／工單欄位，以及必要索引與外鍵。
- `20261104084902_M13_02_CartWorkState`：購物車新增可空的 `draft_json` 核對草稿。
- 包內 `migrations.sql` 是完整冪等 SQL；主機若較舊，可能還有更早的待套用項目，以換版工具顯示的資料庫差異為準。
- 回滾保留新增欄位與所有庫存帳，不執行 Migration Down、不還原舊資料庫覆蓋換版後的交易。

## 換版後先試這些

1. 確認首頁版本、登入、查料及庫存查詢正常。
2. 開新購物車連掃幾筆，核對每筆加入結果。可在掃碼前選儲位，也可先掃料，稍後再分配。同料不同儲位應分列。
3. 沒有條碼時按「查料」，點選物料後核對完整規格及數量。
4. 填專案／工單及儲位分配，重新整理確認恢復；換裝置前先「儲存核對草稿至帳號」。同瀏覽器同一車的第二個分頁應顯示唯讀。
5. 領料可預設本人或明確點選代領人。跨儲位分配的合計須等於清單總量；修改總量先按「儲存總量」。
6. 第一次先核對清單，可放棄未過帳購物車；真正進出料時才確認結帳。審核關閉顯示完成單號，審核開啟顯示「已送審，尚未入帳」。
7. 選轉草稿，確認補齊頁帶入儲位、分配量及已編輯備註。移庫可逐列填目的儲位。完成補齊後再更新 PWA。
8. 若回應遺失，使用原操作重試。快速結帳也可重開原購物車網址查回單據。一般單據用同一分頁的「重試原加入明細」確認結果，再繼續掃碼或送出。

一般單據在掃碼或明細背景更新期間會暫停送審與過帳。數量欄若提示掃碼疑義，先核對完整內容並選用途。盤點表格逐行背景儲存，看到「已儲存」後按「讀取最新盤點結果」，核對狀態及差異再確認或送審。

## 有問題時

- 先保留錯誤畫面、單號／購物車網址及發生時間，方便查日誌。
- 可在系統設定關閉「快速進出一次結帳」，暫時回到轉草稿流程。
- 需回前版時使用包內「一鍵回滾.cmd」，切回曾成功上線的待命版本；資料庫保留新結構與交易紀錄。
- 完整回滾限制見專案 `docs/11-線上更新與回滾.md`；若主機過舊，先確認其相容限制。

## 已驗證與待驗證

開發機完整測試 574 項、Chromium 109 完整掃碼檢查 244 項通過。發布流程會再執行完整測試及校驗。

Edge 109、Android、iPhone、實體掃碼槍／PDA、現場低規格機與 NAS 仍待現場驗證；桌面手機寬度與假鏡頭不算真機通過。請在實際設備上核對連掃、長清單與更新時的操作速度。
