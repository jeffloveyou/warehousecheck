# 需求規格｜功能與使用者故事 v0.1

## 角色與權限
| 角色 | 主要操作 |
|---|---|
| 系統管理員 | 使用者、角色、系統設定、稽核、備份與復原操作流程 |
| 物料管理員 | 正式物料建檔／停用、分類、單位、識別碼、重複合併（需專用流程） |
| 倉庫作業員 | 查詢、建立搜尋索引、依授權完成入出庫、移庫、盤點 |
| 盤點審核者 | 核定盤差、批准庫存調整 |
| 只讀使用者 | 查詢物料、庫存、儲位及允許查看的紀錄 |

預設一般員工可以新增**共用搜尋關鍵字**；正式物料新建先送物料管理員確認。專屬別名是否由一般員工立即生效列為待決事項。

## 功能 FR-01 物料建檔
- 產生或填入**唯一**正式料號；不可因文字名稱相似就擅自合併物料。
- 支援分類（零件、電控、原料、半成品、成品、耗材）、品牌、原廠型號、規格、基本計量單位、追蹤模式、狀態。
- 正式建檔前顯示相似物料候選（料號、原廠型號、精確條碼、搜尋別名），由人判定是否相同。
- 已建立庫存交易的物料不直接更換基礎單位或追蹤模式；以轉換／遷移流程處理。
- 不支援直接刪除已有交易的物料；可停用。

## 功能 FR-02 可自訂搜尋索引（最高優先）
- 任何物料可保存不限業務數量的索引：`伺服放大器`、`伺服AMP`、`Servo Amp`、`伺服的驅動器`、`MR-J4`、用途、現場暱稱等。
- 專屬別名全系統精確唯一；共用關鍵字可掛多個料號。
- 員工可在物料詳情頁直接新增關鍵字，也可以在搜尋失敗時選擇既有物料並加入目前搜尋文字。
- 查詢支援正式料號、名稱、品牌、型號、別名、共用關鍵字、部分符合；中文與英數混合查詢。
- 搜尋結果顯示正式料號、完整規格、類別、儲位、可用庫存及命中原因。
- 新增／停用／修改索引留下人員、時間、舊值、新值；不以使用者的索引誤判執行自動出庫。

## 功能 FR-03 倉庫、儲位與掃碼
- 支援多倉及層級式儲位碼；儲位可設「有效／停用／待驗」等管理狀態。
- 支援一物多儲位、一儲位多物料；正確顯示批號／序號區分。
- 物料與儲位條碼為**選配**：沒有條碼時，所有作業都能以搜尋＋點選完成；使用條碼時採 QR Code，V1 不做標籤列印（ADR-0003）。
- 手機相機掃碼、Windows USB HID 條碼槍與 Android PDA Keyboard Wedge 共用同一文字解析介面。
- 焦點遺失、快速連掃、掃碼尾碼 Enter/Tab、相機權限拒絕皆有可理解的錯誤提示。
- V1 使用即時連線；離線不可提交庫存異動。PWA 快取 UI 不等於離線交易成功。

## 功能 FR-04 期初建帳
- 新倉庫首次啟用由實際清點建立期初單，區分「尚未清點」與「確認為 0」。
- 期初單含：儲位、物料、數量、單位、批號／序號（需要時）、建立人、審核人、時間。
- 期初單送出後產生 StockMovement，禁止直接覆寫結存。

## 功能 FR-05 庫存作業
- 入庫：選入庫原因→掃物料→依追蹤規則輸入批／序號→掃儲位→確認。
- 出庫：選用途／來源單據→掃物料→指定庫存維度→檢查可用量→確認。
- 移庫：掃來源、掃目的、掃物料、輸入量；扣出及入庫同一交易。
- 管理庫存狀態，如 AVAILABLE、QUARANTINE、BLOCKED；可用量需扣除受限制及預留量。
- V1 支援預留庫存（料號＋倉庫層級）；`TrackingMode=None` 的料號可設定允許負庫存至下限，其他料號一律禁止（ADR-0004）。
- 每筆已確認異動有不可變的正負 QuantityDelta、單據來源及操作者；更正用沖銷／反向單據。
- 同時出庫不超賣，重送同一 Idempotency Key 不重扣，資料庫交易失敗全部回滾。
- 批號可有有效期限，序號不得在兩個儲位同時為有效在庫。

## 功能 FR-06 盤點與稽核
- 開立盤點工作、儲位盤點、記錄實盤量、差異審核、產生調整單。
- 盤點基準量與異動期間的衝突需可解釋：V1 優先採儲位凍結，或另行經 ADR 決議。
- 稽核：索引變更、物料主檔變更、單據狀態、權限調整及異常交易。

## 功能 FR-07 輸出／系統維運
- 匯入 Excel 前有試算與錯誤明細，不能默默跳過不合法列；匯出物料與庫存清單。
- 登入、角色授權、內網 HTTPS、日誌、每日備份、還原演練。
- API 文件、繁體中文倉管操作手冊與繁體中文開發手冊。

## 非功能需求（須透過測試確認數字）
- 正確性優先於速度；交易失敗不留下部分扣帳。
- 一般搜尋和頁面查詢應在可接受的現場反應時間內完成；在 M1 規劃預期規模、測試環境和目標秒數，不能預先承諾沒有依據的數字。
- 資料庫支援備份及移轉，完整操作軌跡；測試環境與正式環境隔離。
- UI 至少支援近期 iOS Safari、Android Chrome、Windows Chrome/Edge，以及一款代表性 PDA；實際型號與 OS 列入相容性表。


## NFR-01 使用者端輕量化（V1 必要）
- 目標設備包含舊規格 Windows 電腦，無須獨立安裝大型客戶端，僅用受支援瀏覽器操作。
- UI 優先快速響應與穩定性，不依賴大量動畫、影片或長期背景運算。
- 物料搜尋、庫存查詢、操作歷史需在後端分頁、排序、篩選；每頁最多筆數由 API 控制，禁止下載整庫。
- 條碼槍／PDA 的鍵盤輸入不得被手機相機掃碼程式拖慢；相機掃碼按需載入並於退出時釋放資源。
- 圖片採縮圖、大小限制、延遲載入；必要時壓縮靜態資源。
- 閒置的使用者端不得高頻輪詢；如有即時功能須評估長連線成本和切換版本行為。
- M0 確認最低規格硬體、瀏覽器支援與量化目標；上線前在真實舊機與預期資料量完成測試。

## NFR-02 Windows PC／Linux NAS 伺服器（V1 必要）
- 同一份業務程式碼可部署 Windows PC 與符合執行條件的 Linux NAS；硬體尚未選定。
- 不得使用無法跨平台的核心業務套件、固定磁碟機代號或硬編碼 Windows 路徑。
- 程式設定、憑證、資料庫、附件與發布目錄分離；不同環境以設定檔／環境變數控制。
- Windows 可用原生服務，NAS 可用相容容器或原生服務（若可行），部署方式由 PoC 確定。
- 正式目標應確認 `win-x64`、`linux-x64`；NAS 如為 ARM64 再驗證 `linux-arm64`，不可宣稱適用任意 NAS。
- 兩種環境皆須具備完整安裝、啟動、停止、日誌、備份、還原及發布文件。

## NFR-03 線上更新不中斷正常倉庫作業（V1 必要）
- 應用版本更新時，盡可能允許使用者持續查詢與提交，不要求全體登出或停止正常作業。
- 優先新舊 App 實例並行，健康檢查通過後由反向代理切換新請求，舊實例排空後停止。
- 使用者尚未提交的畫面不可強制重新整理或遺失輸入；PWA 舊資源、舊網頁與新版 API 須有相容期及可理解的更新提示。
- 切換過程不得遺失或重複庫存交易；以資料庫交易、冪等鍵及並行一致性約束驗證。
- Migration 須事先審核並遵守 Expand → Migrate → Contract；不得於新實例啟動時任意執行破壞性變更。
- 新版異常須能切回上一個**資料庫相容**版本，並留下日誌和發版記錄。
- 單機硬體故障、OS 重開機及資料庫故障不在應用版本切換零中斷範圍內；若要真正高可用，需另外規劃備援。
- 應以 M0 PoC 確認主機資源是否容納兩個 App 實例；若不行須記錄替代方案及限制。

## NFR-04 文件、操作與可維護性
- AI Agent 先規劃再實作；建置、測試、Migration、發布預設由使用者手動執行。
- 實作期間同步更新繁體中文開發手冊，包含程式位置、資料流、修改方式、指令、預期結果與除錯說明。
- **不設練習題、課後作業或強制考核**。是否由使用者自行修改程式，由實際需要決定。
