# 物料搜尋索引詳細規格 v0.2

## 1. 產品目標
現場人員不需要記住正確商品名稱或料號。已存在的物料可被附加任意俗稱、縮寫、用途或特徵，例如「伺服放大器」「伺服AMP」「伺服的驅動器」「Servo Amp」，都可找到正式物料；員工不必為同物新增第二張物料主檔。

## 2. 語意分層
- `ItemCode`：公司正式料號，唯一且不可重複。
- `ItemBarcodes`：用掃碼識別的實體條碼／包裝碼，部分條碼需要辨識批號或序號。不是所有文字都適合放條碼表。
- `ExclusiveAlias`：專屬別名，精確命中只能對應單一 ItemId，例「J4-40B 維修備品」。
- `SharedKeyword`：一般俗稱／特徵／用途，可對應多物料，例「伺服AMP」。

## 3. 管理策略
- 一般作業員可新增／撤銷自己建立的共用關鍵字（具稽核紀錄）；預設無權修改正式料號與物料追蹤模式。
- 專屬別名可能需要管理員核准，至少要確認沒有其他物料同名識別衝突。
- 畫面顯示「此關鍵字已被 N 個料號使用」，允許選擇掛到多筆物料但不得自動合併。
- 搜尋失敗時提供「建立搜尋索引」→選現存料號→再次確認產品→儲存；不得在查詢框直接偷偷建立新物料。
- 全部新增／停用留下人與時間。正式索引採停用，不建議硬刪除。

## 4. 搜尋正規化（須先做測試案例）
- Unicode NFKC、大小寫不敏感、前後空白與重複空白整理。
- 中文「的」等字詞是否忽略不可一律套用到精確代碼；只有允許容錯的自然語言搜尋才做寬鬆處理。
- 型號的連字號、斜線、前導零可能具意義；保留原文，另建搜尋用正規化版本，不破壞原始值。
- 英文詞與數字混合、全半形及繁簡差異需以測試資料驗證；不預設可自動理解所有同義詞。

## 5. 搜尋排序
1. 正式料號與可唯一解析的識別碼精確命中。
2. 專屬別名精確命中。
3. 型號／名稱精確命中。
4. 共用關鍵字精確命中。
5. 多詞篩選、部分符合。
6. 模糊相似度（建議候選，不能自動確定料號）。

對應結果必須顯示**命中欄位／命中原因**、料號、完整品名規格、可用量、儲位、必要圖片與品牌。不允許使用模糊排序第一名直接執行出庫。

## 6. 搜尋演算法演進
- M2：精確匹配 + ILIKE/部分比對 + 多詞查詢；建立合適 B-tree 索引。
- M2 之後：量測效能後採 PostgreSQL `pg_trgm` 的 GIN/GiST，驗證中英文、短詞的召回率。
- 若公司資料量大且中文斷詞效果不足，第二階段再評估可商用全文檢索引擎。V1 不以雲端 AI 語意搜尋為必要前提。

## 7. 關鍵驗收情境
- A：EL-000125 有「伺服放大器」「Servo Amp」「伺服的驅動器」索引，任一查詢都可命中。
- B：「伺服AMP」同時附加 EL-000125 / EL-000126，搜尋顯示**兩個**料號及其規格。
- C：員工新增已存在且同料號的索引，系統提示重複，不建立重複紀錄。
- D：員工試圖把已由別的料號專屬占用的精確別名掛到另一料號，須拒絕或改成共用關鍵字流程。
- E：查詢 `MR J4 40B` 可以顯示 `MR-J4-40B` 相似候選，但不能自動當成精確條碼。
- F：搜尋不到「維修用放大器」後，操作員可在 EL-000125 詳情新增該關鍵字；下一次可查得。
- G：已停用的錯誤索引不可再命中，歷史與建立者仍可稽核。
- H：使用者無正式建檔權限時，不能透過搜尋頁繞過審核建立 Item。

## 8. 效能與安全
所有搜尋使用參數化查詢；搜尋字串設長度上限與必要 rate limit。即使某個關鍵字對應大量料號，也必須分頁並設定最大回傳量。效能門檻按真實資料量訂定與測試，不以憑空數字保證。

## 9. 舊電腦搜尋效能
- 所有搜尋先限制最少／最多字數與回傳筆數，使用後端分頁；UI 不載入全部料號和索引。
- 搜尋建議使用節流（debounce）或使用者明確送出，避免每敲一個鍵就執行昂貴的查詢。
- 精確識別碼優先 B-tree 索引；模糊查詢可視資料量與中英文效果評估 `pg_trgm`，實測 SQL 執行計畫。
- 共用關鍵字對應大量料號時必須維持分頁、明確命中原因及人工選擇，不能自動決定出庫對象。
