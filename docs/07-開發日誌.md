### 執行歷程（M0-04 驗證）

|---|---|---|---|
| 1 | `dotnet add src/Warehouse.Infrastructure package Npgsql.EntityFrameworkCore.PostgreSQL` | 安裝 10.0.3 | 未指定版本時取最新穩定版，並寫入 `.csproj` 的 `PackageReference` |
| 2 | `dotnet add tests/Warehouse.IntegrationTests package Microsoft.AspNetCore.Mvc.Testing` | 安裝 10.0.13 | 提供 `WebApplicationFactory`，在記憶體啟動整個 Web 程式 |
| 3 | `dotnet build .\Warehouse.slnx` | 建置成功，0 警告 0 錯誤 | 警告視為錯誤，0 警告才算過 |
| 4 | `psql -U postgres -w`（不給密碼） | `fe_sendauth: no password supplied` | PostgreSQL 預設要求密碼驗證 |
| 5 | 以 `PGPASSWORD=postgres` 連線 | 成功 | winget 無人值守安裝套用預設密碼 `postgres`（**資安風險，見下方**） |
| 6 | 執行與 `init-dev-db.ps1` 相同的 SQL（`\gexec` 條件建立） | `CREATE ROLE`、`CREATE DATABASE` ×2；`warehouse_app` 非超級使用者，兩個 DB 擁有者皆為它 | `\gexec` 把查詢結果當 SQL 執行，配合 `WHERE NOT EXISTS` 做到可重複執行 |
| 7 | 產生 32 字元隨機密碼 → `dotnet user-secrets init/set`、`[Environment]::SetEnvironmentVariable('WAREHOUSE_TEST_DB', …, 'User')` | 設定完成；`warehouse_app` 可登入 `warehouse_dev` | 密碼不進 Git、不顯示在輸出；`user-secrets init` 會在 `Warehouse.Web.csproj` 加 `UserSecretsId` |
| 8 | `dotnet test .\Warehouse.slnx` | **總計 6、失敗 0**（UnitTests 2、IntegrationTests 4） | 新設定的使用者環境變數只對之後開啟的程序生效，本次以 `$env:` 帶入 |
| 9 | `dotnet run --project src/Warehouse.Web --launch-profile http`，查詢各網址 | live 200；ready 200（database 294 ms）；`/api/system/info` 200，`databaseVersion` 17.11；首頁 200 | 版本為 `0.1.0+e9af02b…`，SDK 自動附上 Git commit |
| 10 | `Stop-Service postgresql-x64-17` 後查詢 | live 200（59 ms）；ready **503**（91 ms）；system/info 200、`databaseConnected=false`（3018 ms，觸及 3 秒逾時上限） | live／ready 分離：DB 斷線不代表程式要重啟 |
| 11 | `Start-Service postgresql-x64-17` | ready 恢復 200 | 連線池自動重新連線，不需重啟程式 |

- 觀察：DB 停止時 `/health/ready` 很快失敗，但 `/api/system/info` 等滿 3 秒逾時才回應；兩者都在設計上限內，原因（可能與 Npgsql 對 `localhost` 依序嘗試 IPv6／IPv4 有關）待日後需要時再查。
- 健康檢查 JSON 中的 `+` 會被序列化為 `+`，屬於 JSON 合法跳脫，客戶端解析後相同。
- **資安待辦**：postgres 超級使用者仍為預設密碼 `postgres`，正式環境絕不可如此；開發機建議改為強密碼（見 `docs/04` §2.1）。
